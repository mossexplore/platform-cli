# WiseRec CLI 插件

本插件需配合 WiseRec CLI 使用。请先完成 CLI 配置并申请使用权限，审批通过后即可使用。平台会记录使用情况。

插件在 DeepSeek Harness 中按会话绑定环境与业务，并在宿主运行期间自动保活、显示会话标题和登录状态。

## 开始使用

1. 在 DeepSeek Harness 中安装并启用本插件。若宿主提示重启，请完全退出桌面端和系统托盘后再打开。
2. 确认会话里可以运行 `ml`。执行 `ml auth ping tick --capabilities`，用来确认当前 CLI 支持本插件的调度协议。
3. 每个要使用的会话都单独绑定环境、登录并选择业务。新会话不会继承其他会话的选择，也不会静默使用全局默认环境。

绑定和切换都只影响当前会话，可以随时改到另一个已授权环境，不会把环境和租户永久锁死。

## 多个会话各自绑定

会话 A 和会话 B 的环境、租户可以不同，也可以稍后各自换掉。同一环境的登录是共享的：换会话时切换的是“这个会话正在使用哪套环境和业务”，不需要为每个会话再注册一个账号。

例如：

1. 在会话 A 执行 `ml env list`，用环境标识而不是显示名执行 `ml env use dev`，再执行 `ml business list`，然后 `ml business TENANT_A`。
2. 在会话 B 执行 `ml env use uat` 和 `ml business TENANT_B`。B 的环境与业务不会改写 A，也不会改写全局默认选择。
3. 之后若 A 要改去 sit，只在 A 中执行 `ml env use sit`。B 仍停留在 uat。sit 若尚未登录或尚未选择业务，按命令提示完成即可，A 不会被锁回 dev。

需要指定团队时，使用 `ml business use --tenant TENANT_ID --team TEAM_ID`。只选租户时，`ml business TENANT_ID` 与 `ml business use --tenant TENANT_ID` 都可以。

核对当前会话时运行：

```text
ml context --json
ml env show
ml business show
```

`ml context --json` 不访问网络。请看“上下文模式”“当前环境”“当前业务”“登录状态”和“当前租户”。业务命令仍使用该会话当前绑定的业务。

## 自动保活

插件在宿主进程内检查会话。默认大约每 2 分钟检查一次仍在使用的会话。Windows 上可在 `%LOCALAPPDATA%\WiseRec\dsh-plugins\wiserec-cli\config.json` 修改 `pollSeconds`（60–180 秒）和 `idleWindowMinutes`（默认 120）。首次启用时会生成该文件，修改后需完全退出宿主再打开。检查通过后，并不立刻访问平台。该环境还要空闲满一个保活间隔才会续期，默认约 10 分钟，以本机 CLI 配置为准。因此，插件不能保证登录永不中断。

保活只在这些条件同时满足时进行：插件已启用，宿主正在运行，当前会话已绑定环境，该环境登录仍有效，并且当前会话已选择业务。

下列情况会停下或暂停，退出宿主后也不会在后台继续续期：

- 退出 DeepSeek Harness，或禁用本插件。会话关闭时，插件会取消该会话的登记。
- 会话空闲达到默认 120 分钟（`idleWindowMinutes`）。行尾标识变为“保活已暂停”。回到该会话并继续使用后，下一次检查会重新登记。
- 尚未登录、登录已过期，或当前会话还没选好业务。
- 执行 `ml auth ping stop`。它停止的是当前环境的保活，同一环境里的其他会话也会受影响。
- 休眠、断网，或平台没有确认续期。插件只能在下一次检查时反映结果。

在 Harness 会话中查看状态：

```text
ml auth ping status
```

这条命令只读，不会发起续期。常见“状态”包括：

| 状态 | 含义 |
| --- | --- |
| DSH 插件托管 | 插件已登记当前会话 |
| 插件尚未登记 | 插件还没有检查到这个会话 |
| 插件调度已过期 | 大约 10 分钟内没有新的报到 |
| 已手动停止 | 当前环境执行过 `ml auth ping stop` |
| 登录不可用 | 当前环境还没有可用登录 |
| 等待有效业务上下文 | 已登录，但当前会话的业务还不能用于保活 |
| 平台会话已失效 | 平台侧会话已失效，需要重新登录 |
| 自动保活已关闭 | 当前环境的配置或策略不允许自动保活 |
| 等待绑定环境 | 当前会话还没有绑定环境 |

同时看这几列：

- “插件最近报到”是最近一次检查时间。有报到只说明插件跑过检查。
- “上次平台确认成功”才表示平台已经续期。
- “下次可探活时间”是最早可以再次向平台续期的时间。
- “最近错误”保留最近一次失败说明。

停止和恢复：

```text
ml auth ping stop
ml auth ping start
```

`ml auth ping start` 要在插件已经登记当前会话之后执行。若提示先安装并启用插件，请确认插件已启用、本会话已绑定环境，等一次检查后再试。登录失效时，先在该会话执行 `ml login`，用 `ml auth status` 确认 `status` 为 `valid`，必要时重新选择业务，再用 `ml auth ping status` 查看是否恢复为“DSH 插件托管”。

交互终端里的后台保活仍由 CLI 自己管理。同一环境已有符合条件的 Harness 会话时，插件优先续期，终端状态会显示“DSH 托管，终端待命”。会话关闭或插件报到过期后，仍满足条件的终端会按原间隔接手。这不表示关闭宿主后 Harness 会话仍会被续期。

## 会话标题

登录状态为“有效”，且“当前环境”不是“未绑定”时，插件会把会话标题设成：

- 已得到租户名称：`环境标识环境 · 租户名称`，例如 `sit环境 · 推荐平台`
- 还没有租户名称：`环境标识环境`，例如 `sit环境`

环境标识来自 `ml context` 的“当前环境”，租户名称来自“当前租户”。选择了租户下的团队时，标题仍显示所属租户，不显示团队名。

标题在会话创建或打开、当前操作结束，以及插件定期检查时更新。会话正在运行时不会改标题。登录变成“未登录”或“已过期”后，标题保留最后一次设置的文字，不会自动清空。

手动改过的会话名会被保留。插件只在标题仍是它自己上次设置的名称时，才随环境或租户变化更新。

## 登录与保活状态

`ml context --json` 的“登录状态”只有三种：`未登录`、`有效`、`已过期`。它表示当前会话所绑定环境的本地登录，不表示行尾圆点的颜色。

`ml auth status` 用 `status` 显示 `valid` 或 `expired`，并给出剩余分钟。启用自动保活时，括号中的文字是保活进程或调度状态。这条命令不续期。`businessId` 为 `-` 或空时，先看 `ml context --json` 的“当前业务”，未绑定再选择业务。

插件跟踪的会话会在列表行尾显示圆点。没有圆点表示该会话还没被插件跟踪。鼠标移到会话行上，可以看到状态文字、环境、最近检查时间，以及该环境上次续期成功的时间，时间均为北京时间。界面大约每 10 秒刷新；若连续大约三个检查周期没有新结果，除“已暂停”外会回到“未检查”。

| 颜色 | 行尾文字 | 含义 |
| --- | --- | --- |
| 绿 | WiseRec 保活正常 | 最近一次检查已确认续期，或还没到下一次探活时间 |
| 红 | WiseRec 登录已过期 | 当前环境的登录已过期 |
| 黄 | WiseRec 保活待确认 | 本次检查没有得到确定结果，例如超时、网络或平台尚未确认 |
| 灰 | WiseRec 保活已暂停 | 会话空闲过久、已手动停止，或当前环境不允许保活 |
| 灰 | WiseRec 保活未检查 | 尚未完成检查，或环境、登录刚刚变化 |
| 灰 | WiseRec 等待登录 | 已绑定环境，但还没有可用登录 |
| 灰 | WiseRec 等待选择业务 | 已登录，但当前会话还没选好业务 |

切换环境、重新登录或选择业务后，圆点和标题都要等下一次检查才会更新，默认不超过约 2 分钟。

## 遇到问题时

- 找不到 `ml`：确认 CLI 已安装。改过安装路径后，完全退出宿主再打开，或在本机插件配置中填写 `ml.exe` 的绝对路径。
- 没有圆点：确认插件已启用，并完全退出桌面端和系统托盘后重新打开。
- 灰色“等待登录”：在该会话执行 `ml login`，再看 `ml auth status`。
- 灰色“等待选择业务”：执行 `ml business list`，然后 `ml business TENANT_ID`。
- 红色“登录已过期”：重新 `ml login`。`ml auth status` 的 `status` 应为 `valid`。
- 黄色一直不消失：查看 `ml auth ping status` 的“最近错误”和“上次平台确认成功”。网络恢复后等待下一次检查。
- 状态为“已手动停止”：确认插件仍在运行且“插件最近报到”有时间后，执行 `ml auth ping start`。
- `ml env use` 提示“本地状态正在使用”：用 `ml context --json` 核对是否仍是原环境，稍后再试。切换命令失败时，不要假定环境已经改掉。
