# Skill 目录评审与优化建议 V2

评审日期：2026-11-11。源码基线：`d35b3a585ebd140c221f4bcae0613735916bcd8d`。本稿基于仓库核查、相关测试和同日查阅的 OpenCode 官方权限文档整理，替代原评审中的不准确结论；原稿保留供对照。

评审范围为 `skill/` 中的正式 `wiserec-platform`、`/ml` 与仓库实验入口 `/ml-lab`，并核对 `skill-lab/`、CLI 实现、打包和安装代码。正式 skill 的设计目标是供不同 Agent/harness 共用，包括现有 OpenCode、codeagent 和未来 DeepSeek harness，不绑定 Agent 产品或版本。当前已核查的安装流程面向 Windows；跨 harness 复用不代表 CLI 已支持所有操作系统，也不代表未来 harness 已完成接入验证。

本稿是评审与实施建议，不代表已修改 skill、CLI、安装器或权限配置，也不代表相关改动已经发布。

## 1. 结论与证据边界

现有 skill 已具备按需加载、非交互调用、写操作前核对、结果核验和超时后避免盲目重放等规则。主要改进方向是修正文档漂移，将通用操作规则与 harness 专属接入配置分离，补充机器可读输出与安装来源标识，再通过行为评测决定如何精简内容。

全文区分三类结论：

| 类型 | 含义 | 使用方式 |
| --- | --- | --- |
| 已核实事实 | 可从当前源码、文档或本次测试直接确认 | 可作为修正依据，保留来源 |
| 待验证风险 | 存在合理风险机制，但缺少目标环境复现 | 列出验证条件，不表述为已发生故障或已证实绕过 |
| 优化建议 | 对维护成本、易用性或安全策略的设计选择 | 说明取舍与验收标准，不当作既有事实 |

优先处理安装路径、日志选择说明和实验版分发说明中的错误。正式 skill 不检查 Agent 名称或版本，不按 harness 分叉业务规则；安装位置、快捷入口和权限配置由独立接入说明负责。不能因某条权限模式可能不匹配，就断言整个权限机制失效。只读与无敏感信息是不同维度，不应要求所有只读命令一律免审批。

兼容方式以能力为依据：harness 能向模型提供 skill 及其引用资料、执行 CLI、取得输出和退出状态，并在必要时取得用户确认，即可接入同一份操作说明。工具名称、调用参数和确认交互由 harness 负责映射；缺少完成任务必需的能力时明确报告限制，不靠猜测 Agent 版本决定行为。

用户已确认实验版没有使用者。本稿据此采用“停止维护、仅保留历史资料”的优化方案，不再将实验版是否继续维护列为待确认事项。归档实施尚未完成，以下现状仍按核查时的仓库内容记录。

用户新增强制要求：使用该 skill 执行平台任务时，Agent 不得手动修改代码，也不得借助其他工具间接修改代码。该限制必须置于正式 `SKILL.md` 的“必须遵守”部分，并对所有 harness 生效；具体条款见第 5.4.1 节。本次仅将要求写入评审方案，尚未修改实际 skill。

### 2.2 分发与安装

`setup.py` 将正式 `SKILL.md`、`references/` 下的 Markdown 和 `commands/ml.md` 复制到 Wheel 内的 `wiserec_cli/opencode_resources`，同时生成文件 SHA256 清单。官方 Windows 安装流程再调用资源安装器；单独 pip 安装 Wheel 不会自动完成这一步。

| 用途 | 当前目标位置 |
| --- | --- |
| OpenCode 正式 skill | `~/.agents/skills/wiserec-platform` |
| OpenCode `/ml` | 当前 OpenCode 配置目录的 `commands/ml.md` |
| codeagent 正式 skill | `~/.cac/skills/wiserec-platform` |
| codeagent `/ml` | `~/.cac/commands/ml.md` |

OpenCode 配置目录默认为 `~/.config/opencode`，可由 `OPENCODE_CONFIG_DIR` 指定；共享 skill 路径仍为 `~/.agents/skills/`。成功安装后会清理相应受管理目录内的历史详细版和 `/ml-lab`，并清理当前 OpenCode 配置目录中的旧正式 skill。失败可能使清理尚未完成；历史上使用过的其他自定义目录也不会被自动遍历。

安装器具备资源预校验和父目录符号链接检查，但**没有旧资源恢复机制**：预校验失败时旧资源保留；替换阶段先删除旧资源，复制等后续步骤失败时清理残留，不恢复原文件。不得将此表述为“失败回滚”。

依据：[安装器](../src/wiserec_cli/opencode_install.py)、[安装器测试](../tests/test_opencode_install.py)、[Windows 安装说明](../scripts/windows/INSTALL.md)。

## 3. 已核实的问题

### 3.1 安装路径说明过期

`skill/wiserec-platform/README.md` 仍将 OpenCode skill 位置写为 `~/.config/opencode/skills/wiserec-platform`，与当前安装器的 `~/.agents/skills/wiserec-platform` 不一致。根 README、Windows 安装说明和 CLI 使用手册已使用新路径。

应修正该 README 的安装位置、替换对象和 `OPENCODE_CONFIG_DIR` 的影响范围，或将完整安装步骤集中到 Windows 安装说明，其他文档只保留入口链接。

依据：[skill README](../skill/wiserec-platform/README.md)、[安装器](../src/wiserec_cli/opencode_install.py)。

### 3.2 日志选择说明冲突

`references/commands.md` 开头要求日志编号由用户在交互终端选择，而正式 `SKILL.md` 要求使用 `--select`，CLI 也支持该选项。该命令的索引行已经包含 `[--select SELECTION]`，不需要再重复添加；应删除过时的总述，并将“确认”列中的选择说明移到用途或专门说明中。

应保留的行为边界是：该命令会请求平台归档并写入本地文件；显式传入 `--select` 可避免编号输入提示，但不保证归档已经完成或存在可下载记录。它不是纯只读查询，也没有 `--yes` 确认选项。

依据：[命令索引](../skill/wiserec-platform/references/commands.md)、[正式 skill](../skill/wiserec-platform/SKILL.md)、[日志下载实现](../src/wiserec_cli/commands/train_logs.py)。

### 3.3 实验版说明与分发状态不一致

`skill-lab/wiserec-platform-detailed/SKILL.md` 仍称“随 CLI 安装包提供”，但正式 Wheel 和 sdist 均排除详细版。正式 README 和 `/ml-lab` 入口仍将其描述为仓库实验资料，测试也要求详细版源文件存在。

安装器中的“废弃详细版”指历史受管理安装副本的清理；`verify.py` 校验失败且未接入当前测试或 CI，说明资料已漂移。实验版没有使用者这一事实来自用户补充确认，而非从代码推断。后续停止命令同步和行为维护，仅保留带有历史基线说明的资料；现有入口、测试依赖和文档定位需按第 5.2 节调整。

依据：[详细版入口](../skill-lab/wiserec-platform-detailed/SKILL.md)、[校验脚本](../skill-lab/validation/verify.py)、[资源测试](../tests/test_skill_resources.py)、[打包测试](../tests/test_package_build.py)。原稿引用的 `skill/README.md` 不存在，实际文件是 `skill/wiserec-platform/README.md`。

### 3.4 质量监控命令未列入放行清单

当前示例未为以下六条命令设置专门规则，因此静态匹配时使用 `ml *` 的 `ask`：

```text
ml quality feature list
ml quality wide-featureset list
ml quality wide-featureset feature-assemble list
ml quality wide-featureset label-assemble list
ml quality wide-featureset feature-assemble feature list
ml quality wide-featureset label-assemble feature list
```

这是权限清单覆盖与策略说明问题，不是越权漏洞。核定其结果敏感性与团队审批要求后，可以补充精确的 `allow` 规则，也可以保留 `ask` 并说明原因。

### 3.5 Shell 示例与输出接口不够统一

- 正式 `SKILL.md` 声明示例按 PowerShell 编写，却将 `%LOCALAPPDATA%` 路径作为直接调用回退。该路径表示法不会在 PowerShell 中按环境变量展开；可直接引用 `session.md` 已有的 `& "$env:LOCALAPPDATA\Programs\WiseRecCLI\venv\Scripts\ml.exe" ...` 写法。
- `ml auth status` 当前没有 JSON 选项，使用默认 Rich 表格输出；预检需要解析文本字段。
- `ml context` 使用 `--json`，输出键包含“当前环境”“CLI 版本”“配置路径”等中文名称，应明确键名和与 `auth status.profile` 的对应关系。
- 特征集配置查询固定输出 JSON，服务日志命令不提供统一 JSON 输出，说明中需要保留这些例外。

接口差异增加文档与解析成本，但不直接构成功能错误。新增别名和输出模式应兼容现有调用，不必为了形式统一而改变所有命令。

依据：[会话参考](../skill/wiserec-platform/references/session.md)、[认证命令](../src/wiserec_cli/commands/auth.py)、[上下文命令](../src/wiserec_cli/commands/context.py)、[统一输出](../src/wiserec_cli/output.py)。

### 3.6 安全规则与权限示例存在覆盖差异

`ml login --show-secrets` 成功登录后可打印 Cookie 和 CSRF Token，当前没有类似 `require_tty` 的终端检查。正式 skill 禁止 Agent 使用该选项，README 也有对应拒绝模式；这些约束应与 CLI 行为保护分层描述，不能概括为“只有文字保护”。

资源模板详情、部署模板详情、服务日志和远端文件读取可能返回敏感信息，但 README 示例将其设为 `allow`。是否改为 `ask` 是团队策略选择，应明确便利性与敏感数据访问之间的取舍。`read` 示例只覆盖 `credentials.json`，未覆盖 skill 禁止直接读写的配置和业务文件；历史文件的直接读取策略应单独定义，不能声称原 skill 已明确禁止全部历史文件读取。

正式 skill 对名为 `product` 的环境增加写操作确认要求，当前环境模型没有独立的“受保护环境”标记。生产环境采用其他名字时，无法仅依赖该字面规则获得同样的额外保护；其他写操作核对规则仍然存在。

依据：[正式 skill](../skill/wiserec-platform/SKILL.md)、[权限示例](../skill/wiserec-platform/README.md)、[登录实现](../src/wiserec_cli/auth.py)、[TTY 检查](../src/wiserec_cli/jupyter/terminal.py)、[环境模型](../src/wiserec_cli/models.py)。

### 3.7 内容维护和来源追踪不足

会话预检要求在入口、正式 skill、参考文件和维护者 README 中多次出现。参考文件也包含网格布局、列顺序、时长展示和内部字段映射等内容。这些重复与细节确实存在，但 README 不随正式 skill 安装，实验版也不随正式包分发，不能把所有文件的重复都计作单次 Agent 上下文开销。

`tests/test_skill_resources.py` 主要检查命令提及、链接、名称和分发边界，不能证明参数语义、条件确认或权限策略正确。仓库已有行为评测用例草案，但没有本次可核实的独立模型对照结果。应表述为“缺少可复核的行为评测记录”，而不是断言所有历史修改都未经任何人工验证。

安装后的资源未携带 `manifest.json`，`SKILL.md` 也没有构建版本标记，不利于快速定位来源和同名旧副本。当前构建与安装逻辑未消费 `metadata.cli`、`metadata.platform`；这不代表这些字段对所有 Agent 都没有用途。

`ml-lab.md` 位于正式目录但被分发规则排除，维护者 README 进入 sdist 但不进入安装资源。这些是可以明确说明的边界，并非布局本身必然错误。`.DS_Store` 尚未加入仓库 `.gitignore`，已有未跟踪文件；可另行完善忽略规则，本次保留现有文件。

现有说明还将部分执行工具习惯写成固定前提，例如指定 `skill` 工具、要求工具 `timeout` 使用毫秒、假定所有 shell 工具都没有交互输入。通用 skill 应表达“加载资料”“保证执行等待时间”“使用非交互参数”等操作要求，具体工具与单位以 harness 暴露的能力为准。即使某个 harness 能分配 TTY，也不因此取消本 skill 对交互终端和敏感输出的禁止规则。

## 4. 外部适配与待验证风险

### 4.1 通用 skill 与 harness 接入层分离

正式 skill 只维护一份，以 CLI 的命令和行为为依据，不要求用户先确认 Agent 版本，也不因新增 DeepSeek harness 而复制一套业务规则。

| 层次 | 负责内容 | 兼容原则 |
| --- | --- | --- |
| 通用 skill | CLI 用法、上下文核对、授权要求、结果解释、失败处理、敏感信息约束 | `SKILL.md` 与业务参考文件由所有 harness 共用，不出现按 Agent 版本选择流程的规则 |
| 运行环境说明 | CLI 安装位置、操作系统路径、shell 引号与编码、可用执行能力 | 按实际环境与工具能力选择，不按 Agent 名称猜测；Windows 约束不伪装成跨平台能力 |
| harness 接入层 | 资料加载、快捷入口、工具参数映射、权限配置、安装目标目录 | 单独维护，不进入所有 Agent 必读的业务上下文；新增 harness 只补必要接入能力 |

`/ml` 是现有接入方式，不是使用 skill 的必需条件。没有 slash command 或名为 `skill` 的工具时，harness 可以通过自身机制加载同一份正文和相对路径引用资料，无需修改业务规则或生成专属 skill。

现有 README 的 OpenCode 权限 JSON 应迁到独立接入说明。外部软件的配置语法可能变化，接入说明需保证示例对其声明的环境有效，但不把这种配置差异提升为 skill 的版本门槛。[OpenCode 官方权限文档](https://opencode.ai/docs/permissions/)仅作为该接入方式的参考，不定义通用 skill 的执行协议。

### 4.2 调用形式可能影响规则匹配，尚未证实绕过

以下属于接入层验证，不是正式 skill 的通用使用前提。需要验证的形式包括裸 `ml`、带引号的绝对路径、PowerShell 调用运算符、Git Bash 变量形式、编码设置前缀以及复合命令。

官方 V2 文档说明 shell 资源来自扫描器，复合命令可能拆成多个资源，无法安全分析的动态求值会产生扫描错误。最终结果还受有效规则与默认策略影响。因此，“没有命中某条 `ml *`”不等于“命令未经审批执行”。[官方匹配与扫描说明](https://opencode.ai/docs/permissions/#scanner)

不要直接把 `*ml.exe *`、`*ml.cmd *` 等字符串模式当成已验证方案；引号、大小写、路径归一化和扫描器输出都可能影响结果。应先在隔离配置与无真实凭据的测试环境中记录实际匹配资源，再制定最小必要规则。

### 4.3 编码与终端检查的边界

CLI 的 `configure_windows_output` 会将可重配置的 Windows 非 TTY 输出流设为 UTF-8，但这不能保证接收端采用相同解码方式。不能断言“只有 PowerShell 管道处理才需要编码设置”。更合适的说明是：出现编码不一致时，按实际 shell、版本及输出接收方式处理，并验证中文结果；无需在所有调用前固定加前缀。

现有 `require_tty` 同时检查 stdin 和 stdout。若用于 `--show-secrets` 加固，至少应覆盖这两个方向，防止 stdin 为终端而 stdout 被重定向时仍输出秘密。TTY 检查只能限制非终端调用和重定向，不能识别调用者是否为 Agent，也不能代替权限和脱敏策略。

### 4.4 内容精简的收益需要评测

缩短重复说明、将关键规则前置，可能减少上下文开销和阅读负担；是否改善目标模型的遵循率，目前没有实测结论。某些无 JSON 输出的命令仍需要文本字段说明；选择编号、原始数值单位和任务状态含义也可能直接影响正确操作，不能一律删除。

## 5. 优化方案与验收标准

### 5.1 先修确定的文档错误

修正安装路径与替换范围；消除日志编号交互说明冲突；改正详细版“随包提供”的表述；统一 PowerShell 路径示例；补充输出模式例外，将 harness 专属权限示例放入独立接入说明。

验收时核对所有本地链接、命令语法、安装路径和分发说明。质量监控的六条规则需先确定审批策略，再修改示例。此阶段无需改变 CLI 行为。

### 5.2 停止维护实验版，仅保留历史资料

实验版已确认没有使用者，后续不再新增能力、不再随 CLI 命令变化同步，也不再要求历史校验脚本适配当前命令树。保留资料用于追溯原设计和提取可复用内容，不作为当前 CLI 的操作依据。

归档实施应完成以下事项：

| 对象 | 处理方式 | 验收标准 |
| --- | --- | --- |
| `skill-lab/` 资料 | 保留历史快照，增加醒目的停止维护说明、归档日期与来源提交；不宣称该快照全部校验通过 | 能识别历史基线，明确不适用于当前命令指导 |
| `/ml-lab` 入口 | 从活跃的 `skill/commands/` 移出并随历史资料保存；删除正式说明中的使用引导 | 现有 slash command 仅保留 `/ml`；其他 harness 可直接加载通用 skill，不再引导安装或加载实验版 |
| 历史校验脚本与用例 | 随资料归档，不接入当前 CI；有价值的逻辑和用例经复核后单独迁入正式检查 | 不为消除历史漂移而继续维护整套实验版 |
| 测试与构建依赖 | 调整要求实验版活跃存在的测试和构建复制逻辑，正式构建不依赖归档资料 | 正式 skill 测试和构建可独立通过 |
| 分发边界与旧副本清理 | 保留并核对 Wheel、sdist 排除规则及防回归断言；继续保留安装器清理历史副本的能力 | 归档资料不进入正式包，存量管理目录仍可清理 |

本次仅在评审文档中明确方案，尚未移动入口、归档目录或修改测试与构建逻辑。

### 5.3 部分生成命令索引，保留语义维护

可以从 Click 命令树生成命令路径、声明的参数和选项、解析器暴露的默认值与范围，以及是否存在 `--yes`、`--output` 等选项。新增生成脚本可采用 `--check` 模式，防止生成物漂移。

以下内容不能只靠参数签名推导：

- 什么时候真正询问确认、dry-run 是否完全无副作用。
- 输出参数是否接受 JSON、固定 JSON 输出、字段语义及 stdout/stderr 混用情况。
- 敏感信息级别、远端与本地副作用、超时后的核验方法。
- 默认分页及服务端限制、跨字段校验、返回结果是否代表远端完成。

建议用小型人工维护的命令语义清单补充生成信息，再为关键行为增加有意义的测试。清单表达通用的副作用、敏感性和用户授权要求，接入层再映射为自身权限机制；不能简单以“只读”决定 `allow`，也不把某个 harness 的权限字段写成通用业务语义。

| 检查层次 | 建议覆盖 |
| --- | --- |
| 静态一致性 | 已识别命令示例中的选项、参数、生成索引、文件链接与分发清单 |
| CLI 行为测试 | 确认分支、JSON 可解析性、固定输出例外、归档未完成和超时状态 |
| harness 接入测试 | 各接入环境中，资料加载、执行结果回传和普通查询、敏感读取、写操作、禁止命令的预期处理；确认直接编辑和间接执行均不能被用于修改代码 |
| 内容规模检查 | 字符数变化作为评审提示，不以硬上限迫使删除必要限制 |

### 5.4 建立基线后精简 Agent 文档

保留 `ml.md` 的加载入口、用户需求参数、无需求时的用法，以及加载失败即停止、不把用户文本直接拼接为命令的要求。将详细会话规则集中到正式 skill 与会话参考，不机械删掉所有重复提醒。

`ml.md` 作为现有 harness 的入口适配文件，其专属占位符和工具调用约定不扩散到通用正文。`SKILL.md` 与业务参考不依赖 OpenCode、codeagent 或 DeepSeek harness 的名称、版本、特定工具名、固定超时参数名或单位，也不假定资料一定由 slash command 触发。仅在现有工具说明不足以执行任务时确认缺失能力，不增加每次调用前的 harness 探测步骤。

正式 `SKILL.md` 建议依次组织为：必须遵守、首次确认与上下文失效条件、调用方式、按任务读取参考。将写前核对、用户授权、超时后的处理和敏感输出限制拆成清晰条目。

在“受保护环境”能力尚未实现前，保留现有 `product` 保护，并明确实际生产环境名称的核对办法；不要提前用一个 CLI 尚不提供的字段替换现有规则。

参考文件优先保留参数范围、ID 区别、字段路径、原始单位、分页、退出码、副作用及核验方式。纯视觉布局可以移至用户手册；没有 JSON 输出或仍依赖表格编号的操作保留必要文本说明。重写前后用相同任务集评测，确认没有削弱写操作核对和异常处理。

#### 5.4.1 强制禁止 Agent 修改代码

以下条款必须作为正式 `SKILL.md` 中的硬性约束，不得仅放入可选参考文件，也不得在内容精简或新增 harness 接入时弱化：

> **禁止修改代码**
>
> 1. 本 skill 用于通过既有 CLI 操作平台，不承担代码开发或修复。执行本 skill 任务期间，Agent 不得创建、改写、替换、删除或打补丁修改代码，包括 CLI 源码及已安装程序、依赖库、本地或远端业务代码、脚本和 Notebook 代码单元。
> 2. 禁令同时覆盖直接编辑和间接修改：不得使用文件编辑工具、补丁、shell 重定向、文本替换、临时脚本、`ml jupyter files`、`ml jupyter exec`、Notebook 执行或委托其他 Agent 等方式完成代码修改。不得将改码包装成“排障”“临时修复”“兼容处理”“绕过报错”或“任务准备”。
> 3. 不得通过复制一份代码再修改、生成替代实现、运行时注入或猴子补丁等方式规避限制；也不得修改 skill、权限规则或执行配置来解除该禁令。
> 4. 仅使用当前已安装 CLI 支持的命令和参数。出现命令缺失、参数不支持、程序缺陷或任务必须修改代码的情况时，停止受影响操作，报告实际命令、错误及阻塞原因，交由维护人员在独立开发流程处理。不得先修改代码再继续，不得将用户对平台操作或故障排查的授权视为改码授权。
> 5. 通过 CLI 执行已授权的业务操作仍须遵守原有确认和核验要求；能够写文件或执行远端程序的命令不构成改码例外。执行既有程序前，应确认任务及已知副作用不涉及上述代码修改；无法确认时停止该执行并说明限制。

该限制针对 Agent 使用 skill 处理平台任务的过程，不禁止维护人员在独立开发流程中修订 CLI 或 skill。本评审提出的 CLI 改进属于后续开发工作，不得由正在执行平台任务的 Agent 自动实施。

普通查询、按授权更新非代码业务参数、下载结果和生成报告等操作不因本条一概禁用，但不能覆盖代码文件，不能借参数传入用于改码的程序。执行既有 Notebook 时，代码单元必须保持不变，其执行内容也不得用于修改其他代码；若无法确认这一点，则停止执行。判定依据是实际操作和副作用，不仅是文件扩展名或命令名称。

验收需覆盖“命令报错后直接修源码”“修改已安装依赖”“通过远端 exec 或文件写入修改代码”“生成临时补丁或替代脚本”“改写 Notebook 代码单元”“委托其他 Agent 修改”“修改 skill 解除限制”等场景。预期均为不实施修改、保留代码原状并报告阻塞；同时验证正常查询和已授权的非代码业务操作仍可完成。

skill 文本定义行为约束，不等于已实现文件系统强制隔离。接入层应结合可用权限、受限执行或只读挂载保护代码位置，并覆盖 shell 与远端执行通道；不能只禁用编辑工具就宣称技术上已阻止改码。具体防护由各 harness 接入实现，通用禁令保持一致。

### 5.5 增加安装来源信息，准确描述失败行为

可在构建资源时写入来源 CLI 版本及资源摘要，版本读取根 `versions.toml`，不在多个源文件中手工维护。生成后再计算校验值，保证清单对应最终资源；如新增安装文件，需要同步调整白名单和分发测试。

这里追踪的是 CLI 与 skill 资源的来源，不是 Agent 版本。版本不一致是排查信号，不自动等于不兼容；同版本也不能证明没有同名旧副本或手工修改。诊断应结合实际加载路径、来源版本和资源摘要。

先将安装失败说明修正为真实行为。若另行实现旧资源恢复，需要设计备份、替换、跨目录失败与恢复测试，不能仅修改文案就宣称支持回滚。

### 5.6 CLI 配合改动

| 建议 | 兼容性与验收重点 |
| --- | --- |
| `auth status` 增加 JSON 输出选项 | 默认表格行为保留；验证认证缺失、过期和未选业务等状态，不输出凭据 |
| `context` 增加 `-o json` 别名 | 保留 `--json` 和现有字段；定义选项冲突处理 |
| 可选：`context` 返回认证摘要 | 保持无网络、无自动登录；凭据不存在时可报告状态，避免把“读取本地摘要”等同于“必须登录” |
| `--show-secrets` 增加输出保护 | 在敏感输出发生前检查 stdin/stdout；测试重定向组合，明确 TTY 并非安全身份边界 |
| 增加受保护环境标记 | 定义旧配置默认行为、现有生产保护兼容方式、展示与执行约束；仅输出标记不会自动产生 CLI 强制保护 |
| 可选：模板详情默认脱敏 | 单独评估依赖原始 JSON 的调用方，明确脱敏范围与原值访问权限 |

这些方案均尚未实施。修改已有命令需同步 `docs/WiseRec CLI 使用手册.md`，并遵守其四类小节、无版本信息等规范。只增加已有命令选项不触发“新增命令必须递增”的特定规则，但不等于可以用已发布版本覆盖交付；正式发布仍遵守新版本与不可变产物要求。涉及版本调整时只改 `versions.toml`，再运行同步和检查脚本。

### 5.7 权限策略与行为评测

通用行为评测使用同一份 skill、任务集和验收标准，验证查询、敏感读取、写操作、交互命令、凭据输出及禁止修改代码的处理。各 harness 的接入测试负责检查资料加载、执行结果、用户确认和权限机制是否正确映射这些要求；不为某个 Agent 单独放宽或重写业务规则。文件读取规则按实际路径格式验证；仅限制 `read` 工具不能替代 shell 的文件访问控制。

演示环境可作为行为评测基础，但需先核对场景覆盖、隔离路径和故障注入能力。建议准备 15 至 20 条任务，覆盖普通查询、翻页、重名、跨消息复用、环境切换、写前核对、超时、认证过期、未选业务及禁止操作。缺失的模拟场景需先补齐，不使用真实生产操作补测试。

每条任务记录允许和禁止的调用、必要确认点及完成判据；记录模型、harness、shell 和 skill 来源，所用软件版本仅作为复现元数据，不成为 skill 的准入条件。指标同时包含任务完成率、不必要预检次数、写前核对遗漏、禁止调用尝试、代码修改尝试和超时后盲目重放。禁止改码场景还需核对测试代码文件前后内容及实际工具调用，不能仅凭 Agent 回复判断通过。对存在随机性的模型重复运行关键场景，避免用一次结果证明优化有效。记录中不保留真实凭据或敏感输出。

未来 DeepSeek harness 接入时，复用同一份 skill 与评测任务，只补充其加载、执行、结果回传和必要确认机制的映射。当前先消除正文中的 harness 耦合，不以尚未提供的 DeepSeek harness 细节阻塞通用内容优化，也不提前宣称已经验证兼容。

## 6. 实施顺序与完成条件

| 顺序 | 工作 | 完成条件 |
| --- | --- | --- |
| 1 | 修正确定的文档错误，加入禁止修改代码的硬性约束 | 路径、命令、分发说明和链接与当前实现一致；正式 skill 顶层明确禁止直接及间接改码，规定遇阻停止与报告 |
| 2 | 分离通用 skill 与接入配置，归档实验版 | 通用正文不依赖 Agent 产品或版本；实验版停止维护、仅保存历史资料，入口与构建依赖完成清理 |
| 3 | 建立命令语义清单与针对性检查 | 索引生成可复核；权限覆盖不再等同于全部只读放行 |
| 4 | 建立通用行为评测与接入检查基线 | 以现有 Windows CLI 环境开始，统一任务集可供各 harness 复用，接入差异单独验证 |
| 5 | 精简正式 skill 与参考文件 | 上下文开销可比较，关键行为不退化 |
| 6 | 分批实施 CLI、权限与安装来源改进 | 每项通过相应行为、兼容与分发验证，再同步文档 |

权限和敏感输出问题的验证可前置，不必等待全文重写。纯文档修改采用结构、链接、命令示例与差异检查，不新增没有行为价值的测试；正式出包仍须完成仓库规定的完整门禁。

## 7. 尚待确认的事项

1. 各 harness 接入时的资料加载、CLI 执行、结果回传和用户确认能力；这些信息用于接入实现，不作为通用 skill 的版本前置检查。
2. 需要提供专属权限配置时，完整路径、变量、编码前缀和复合命令在该接入环境中的实际权限结果。
3. skill 及相对路径参考文件在各接入方式中的访问与加载行为；DeepSeek harness 的具体接入细节在实施时核对。
4. 敏感只读命令的审批策略，以及实际生产环境的识别和兼容要求。
5. 演示环境对评测场景的覆盖程度，以及精简方案在目标模型上的实际效果。

以上事项在验证完成前保持为待确认项，不据此宣称权限绕过已成立或文档精简必然有效。实验版没有使用者已由用户确认，后续按第 5.2 节停止维护并保留历史资料。
