# 1.0.7.1 正式发布说明

CLI 与权限管理系统统一为 1.0.7.1，上一正式版本为 1.0.5.7。本次需要将权限数据库结构从 10 显式迁移到 11；GitHub 发布不会自动升级生产服务、迁移生产数据库或修改业务准入策略。

## 新增与改进

- CLI 新增资源模板、部署模板查询及 `ml model deploy`，按关联资源模板预览区域、资源和配置后确认部署；完善可选资源与加速器字段兼容处理。
- 新增 `ml featureset wide export SET_ID`、`ml featureset model export SET_ID`，原样保存 CSV，支持中英文导出、指定文件路径和 JSON 摘要，重名自动编号、不覆盖已有文件。请求使用当前环境的业务 ID。
- Windows 安装同步安装 OpenCode skill 和 `/ml` command；提供本地构建安装入口。重装或升级保留 `current` 和自动保活设置，原配置损坏或原环境被删除时保留原文件并报错。
- profiles 新增 `alias`，环境列表显示别名及四列中文表头，环境切换仍使用 `name`。权限申请结果和详情显示环境别名，新的审批结果保存当时的显示名。
- 登录取得账号及执行环境命令后查询任意环境的当前有效授权；无有效授权时提示配置的权限服务 `/apply` 申请入口和代理排除说明。查询失败不会误报为无授权，尚无当前环境账号时提示先登录。
- 权限管理支持批量调整多个人员的授权；数据分析支持可配置排行及人员姓名。
- 环境管理新增“默认开通”标识，审批只预选启用且带此标识的环境，提供恢复默认、全选和清空；无默认环境时不预选。标识仅控制预选，不自动审批或修改已有授权；预览后配置变化需重新核对。
- 调整环境管理的默认开通、平台地址、创建时间和修改时间列宽，完善紧凑表格展示。

## 使用前提与升级影响

业务命令需配置当前环境地址、权限服务地址，完成登录与业务选择并通过实时鉴权。部署服务前先迁移数据库，再安装新 CLI；旧权限服务缺少用户授权查询接口时，新 CLI 会明确提示更新服务。`access_control.url` 应包含正确服务前缀，例如 `https://权限服务地址/cli-permission`。

备份 CLI 配置后安装。原环境必须仍在新包 profiles 中，否则更新停止；其他环境定义与权限服务设置仍由包内模板更新，安装后核对地址和业务。别名不是命令参数，`ml env use` 仍使用原始标识。权限服务环境显示名与 CLI alias 应保持一致。OpenCode 资源会随安装更新，不应在安装目录中保存个人修改。

## 数据库迁移与回滚

比较上一正式版源码与本次迁移、模型，结构从 **10 → 11**，新增 `environments.default_grant BOOLEAN NOT NULL DEFAULT 0`。已有环境默认关闭，人员、管理员、授权与申请记录保留。先在独立库演练恢复和迁移；维护窗口停写后做最终数据库及配置备份，然后由一个进程显式执行迁移，核对数据并验收后再放行。不得覆盖真实 service.env、重新创建已有管理员或手改 schema_versions。

本版没有降级迁移，旧版健康检查要求结构 10，不能只切回旧镜像连接结构 11。回滚需要停止新写入，恢复结构 10 最终备份及原配置，再启用旧摘要；会丢失备份后的审批、授权、默认配置、日志和审计。详见 `Docker-upgrade-1.0.7.1.md`。

## 验证范围与限制

正式发布门禁包含 CLI 和权限服务测试、浏览器时区与环境标签、审批快捷选择测试；Windows 联网/禁止联网取包的离线安装、同版本重装与正式 CLI 1.0.5.7 升级、环境选择保留；同一 linux/amd64 候选镜像的 MySQL 健康、结构迁移、管理员登录、授权允许/拒绝、用户授权查询、申请审批、日志持久化、数值图表 JSON、重启和目录挂载配置更新；来源证明、Docker save/load 往返与附件组装。正式发布须在全部门禁成功且下载草稿独立复核后执行。

真实业务平台中英文 CSV 导出、模型部署、远端 Jupyter/Web Studio、生产 MySQL、真实浏览器视觉验收未在本次自动测试中验证；模拟接口与测试库通过不代表这些联调已完成。跳过测试不算通过，部署方仍需按指南完成真实环境验收。
