# 权限管理系统数据看板图表筛选与占比样式优化设计方案

> 文档状态：已确认并进入开发实施  
> 适用模块：`access-service`（权限管理系统数据看板 `/cli-permission/admin/analytics`）

---

## 1. 背景与目标

当前数据看板「数据分析」卡片已支持 6 个视图（命令分布、调用趋势、调用次数分布、调用次数排行、版本分布、调用环境情况），但存在以下使用限制：

1. **「调用次数分布」**固定仅展示 Top 5 命令 + 其他命令，采用底部图例展示，无法按需查看 TOP10/TOP20/TOP30/TOP50/全部 命令，也无法在图内直接按环境切换查看单环境的命令占比；
2. **「调用次数排行」**固定仅展示 Top 10 命令，无法调整 TOP 数量，也无法在图内按环境筛选排行；
3. **「版本分布」**无法在图内直接按环境切换查看单个环境的 CLI 版本分布。

本次改造目标：

1. **调用次数分布**：
   - 图表下方新增 2 个下拉框：**TOP命令**（`TOP10`、`TOP20`、`TOP30`、`TOP50`、`全部`，默认 `TOP10`）与 **环境**（`全部` 及当前全部环境标识，默认 `全部`）；
   - 饼图样式调整为与「版本分布」一致：**去掉底部图例**，直接在饼图外侧通过引导线标注 **`命令 (占比%)`**。
2. **调用次数排行**：
   - 图表下方新增 2 个下拉框：**TOP命令**（`TOP10`、`TOP20`、`TOP30`、`TOP50`、`全部`，默认 `TOP10`）与 **环境**（`全部` 及当前全部环境标识，默认 `全部`），样式与交互同「调用次数分布」。
3. **版本分布**：
   - 图表下方新增 1 个下拉框：**环境**（`全部` 及当前全部环境标识，默认 `全部`），按所选环境动态展示该环境下的全量 CLI 版本分布。

本次改造不涉及数据库表结构变更与迁移，不引入第三方前端图表库。

## 2. 交互与界面布局设计

### 2.1 图表下方筛选栏位置与显示规则

在 `analytics.html` 的 `.analytics-plot` 容器内，将新增的图表级筛选栏 `.analytics-plot-controls` 放置在**图表画布（`.analytics-plot-scroll`）与图例（`.analytics-plot-legend`）下方**、趋势数据表上方，并与图表视图联动显隐：

| 当前视图 | 显示的图表下方下拉框 | 默认值 |
| --- | --- | --- |
| 命令分布（`commands`） | 无（隐藏筛选栏） | — |
| 调用趋势（`trend`） | 无（隐藏筛选栏） | — |
| **调用次数分布（`distribution`）** | `TOP命令` + `环境` | `TOP10`、`全部` |
| **调用次数排行（`ranking`）** | `TOP命令` + `环境` | `TOP10`、`全部` |
| **版本分布（`versions`）** | `环境` | `全部` |
| 调用环境情况（`environments`） | 无（隐藏筛选栏） | — |

交互细节：
- **独立状态记忆**：3 个视图各自维护独立的筛选状态（例如在「调用次数分布」选了 `TOP20 + prod`，切换到「调用次数排行」后仍保持其自身的 `TOP10 + 全部`，切回「调用次数分布」时保留 `TOP20 + prod`）。
- **无刷新局部更新**：切换下拉框时仅异步请求对应图表数据并重绘当前 SVG，不刷新整个页面，也不重置当前选中的图表视图。
- **空数据友好提示**：若某个环境在当前时间范围内无调用记录（如已配置但近期未调用的环境），在画布区域内展示空态提示（如「所选环境下暂无调用记录」），**下拉框保持可见且可继续切换**，不会隐藏整个面板。
- **样式复用**：下拉框采用与页面现有 `select` / `.analytics-ranking-actions` 一致的紧凑风格，左/居中对齐，包含清晰标签文案（`TOP命令`、`环境`），窄屏自动换行。

### 2.2 「环境」下拉框选项来源与顶部全局筛选联动

1. **选项来源**：
   - 取 `environments` 表中所有环境标识（`Environment.name`）与当前筛选时段 `cli_call_logs` 中出现的非空 `CallLog.environment` 的**并集**，去重后按环境标识字典序排列；
   - 首项固定为 `全部`（value 为空字符串 `""`），其余为全部环境标识（如 `dev`、`prod`、`staging`、`test`）。
   - 这样既能覆盖系统当前配置的全部环境，也能保留历史日志中出现过的环境标识。
2. **与顶部「更多筛选 -> 环境」的联动**：
   - 当顶部全局筛选未指定环境（默认空值）时，图表下方的「环境」下拉框默认选 `全部`，可自由切换任意环境；
   - 当顶部全局筛选已指定具体环境（如 `environment=prod`）时，全页数据已限定在该环境内：图表下方的「环境」下拉框默认选中该环境且置为只读/禁用状态（附提示「已由顶部筛选限定」），避免与顶部全局筛选产生语义冲突。

## 3. 各图表详细规格

### 3.1 调用次数分布（`distribution`）

1. **下拉框**：
   - `TOP命令`：`TOP10`（`10`）、`TOP20`（`20`）、`TOP30`（`30`）、`TOP50`（`50`）、`全部`（`all`），默认 `TOP10`；
   - `环境`：`全部`（`""`）及全部环境标识，默认 `全部`。
2. **统计与归并口径**：
   - 筛选条件 = 页面顶部 `filters` +（若选择了具体环境）`CallLog.environment == chart_env`；
   - 计算当前条件下的总调用次数 `sub_total`；
   - 当 `TOP命令` 为 `10`/`20`/`30`/`50` 时：取调用次数最高的 Top N 命令，若 `other = sub_total - sum(topN) > 0`，追加 1 项 `{'label': '其他命令', 'value': other, 'href': ''}`，使所有扇区占比之和恒为 100%（以 `sub_total` 为分母，真实反映 TOP 命令在整体或该环境中的占比）；
   - 当 `TOP命令` 为 `all`（全部）时：返回全部有调用记录的命令，不生成「其他命令」。
3. **视觉样式改造（对齐「版本分布」）**：
   - 抽离通用外侧标注环形饼图函数 `calloutPie(items)`，供「调用次数分布」与「版本分布」复用；
   - **隐藏底部图例**（`legendItems([])`）；
   - 在饼图外侧通过引导线直接展示 **`命令 (占比%)`**，例如 `ml train list (42.5%)`；
   - 色板沿用 12 色扩展色板循环着色，「其他命令」固定使用中性灰 `#a9aeb8`；
   - 当选项为 `TOP20`/`TOP30`/`TOP50`/`全部` 导致标注较多时，画布高度随单侧标注数自动扩展（`Math.max(340, maxSideCount * 22 + 44)`），配合左右分侧与双向垂直避让算法，避免标签重叠或裁切；
   - 环心居中展示当前条件下的总次数 `sub_total` 与 `次授权检查`；
   - 鼠标悬停提示 `${item.label}：${item.value} 次（${pct}%）`；点击正常命令扇区/标注时，下钻至 `/cli-permission/admin/calls` 并自动携带 `command_exact=<命令>` 及当前所选 `environment`（如有）。

### 3.2 调用次数排行（`ranking`）

1. **下拉框**：
   - `TOP命令`：`TOP10`、`TOP20`、`TOP30`、`TOP50`、`全部`，默认 `TOP10`；
   - `环境`：`全部` 及全部环境标识，默认 `全部`。
2. **统计口径**：
   - 筛选条件 = 页面顶部 `filters` +（若选择了具体环境）`CallLog.environment == chart_env`；
   - 按 `COUNT(*) DESC, CallLog.command ASC` 排序，按 `top` 参数截取前 N 条（选 `all` 时不截断，返回全部）。
3. **视觉与交互**：
   - 沿用现有 `categoryBars()` 柱状图样式，横坐标为 `命令名称`，纵坐标为 `次数`；
   - 图例随环境状态动态文案：全部环境时显示 `按命令汇总的授权检查次数`，单环境时显示 `按命令汇总的授权检查次数（环境：<env>）`；
   - 柱子数量较多（如 `TOP30`/`TOP50`/`全部`）时自动按 `Math.max(560, graphic.clientWidth, items.length * 130 + 70)` 扩展画布宽度，支持横向滚动并显示滑动提示；
   - 点击柱子下钻至 `/cli-permission/admin/calls` 并携带 `command_exact=<命令>` 及当前所选 `environment`。

### 3.3 版本分布（`versions`）

1. **下拉框**：
   - `环境`：`全部` 及全部环境标识，默认 `全部`。
2. **统计口径**：
   - 筛选条件 = 页面顶部 `filters` +（若选择了具体环境）`CallLog.environment == chart_env`；
   - 按 `COUNT(*) DESC, CallLog.cli_version ASC` 全量聚合（不合并为「其他版本」），空值兜底 `'未知版本'`。
3. **视觉与交互**：
   - 复用 `calloutPie()` 环形饼图，无底部图例，图内标注 **`版本号 (占比%)`**；
   - 环心总数为当前所选环境的授权检查次数，占比分母为该环境总次数；
   - 点击扇区/标注下钻至 `/cli-permission/admin/calls` 并携带 `cli_version=<版本号>` 及当前所选 `environment`。

## 4. 后端接口与数据流设计

### 4.1 初始页面加载（`GET /cli-permission/admin/analytics`）

保持初始响应轻量，仅返回默认视图数据与环境选项列表：
- `chart['distribution']`：默认 `TOP10` + 全部环境（若顶部筛选已指定环境则沿用）；
- `chart['ranking']`：默认 `TOP10` + 全部环境；
- `chart['versions']`：全量版本 + 全部环境；
- `chart['environments']`：全量环境调用次数；
- `chart['environment_options']`：当前全部环境标识数组（例如 `["dev", "prod", "staging"]`）；
- `chart['locked_environment']`：顶部全局筛选中的 `params['environment']`（空字符串表示未锁定）；
- `chart['query_url']`：图表异步查询基础路径（携带当前 `begin`、`end`、`grain` 及顶部筛选参数，确保默认 7 天窗口在后续切换下拉框时时间范围保持锁定不漂移）。

### 4.2 新增图表局部查询接口（`GET /cli-permission/admin/analytics/chart`）

参考现有 `ranking-commands` / `ranking-actors` 局部刷新机制，新增轻量 JSON 接口专供图表下拉框切换使用：

- **路径**：`GET /cli-permission/admin/analytics/chart`
- **鉴权**：沿用 `admin_session(request, db)`；未登录返回 `401`（前端跳转 `/cli-permission/login`）。
- **查询参数**：
  - 公共筛选参数（与 `/admin/analytics` 一致）：`grain`、`begin`、`end`、`username`、`environment`、`business_id`、`cli_version`
  - 图表参数：
    - `view`：必填，枚举 `distribution` | `ranking` | `versions`（其他值返回 `400`）
    - `top`：可选，枚举 `10` | `20` | `30` | `50` | `all`，默认 `10`（仅 `distribution`、`ranking` 使用，非法值返回 `400`）
    - `chart_env`：可选，最大长度 `64`，默认 `""`（空表示全部环境）
- **响应格式**（`200 OK`, `application/json`）：
  ```json
  {
    "view": "distribution",
    "top": "10",
    "chart_env": "prod",
    "total": 128,
    "items": [
      {
        "label": "ml train list",
        "value": 64,
        "href": "/cli-permission/admin/calls?begin=...&end_exclusive=...&environment=prod&command_exact=ml+train+list"
      }
    ]
  }
  ```
- **前端缓存与竞态保护**：
  - 使用 `Map` 按 `${view}|${top}|${chart_env}` 缓存当前页面的查询结果，切回已查组合时零请求即时重绘；
  - 使用 `AbortController` + 递增请求序号（同 `analytics-rankings.js`），避免快速连续切换下拉框时旧响应覆盖新结果；
  - 请求失败时回滚下拉框值并展示行内错误提示，保留原图表。
- **数值类型安全（遵循 AGENTS.md 规范）**：
  - 所有聚合计数经 `count_value()` 转为 Python `int`，确保 MySQL 返回 `Decimal` 或空集返回 `None` 时 `JSONResponse` 与 `chart|tojson` 均安全序列化为数字类型。

1. **后端自动化测试（`pytest access-service/tests`）**：
   - 验证 `/admin/analytics` 初始返回 `distribution` 为 TOP10 + 其他命令、`ranking` 为 TOP10、`environment_options` 覆盖 `environments` 表与日志中的全部环境标识；
   - 验证 `/admin/analytics/chart`：
     - `view=distribution` 配合 `top=10/20/30/50/all` 与 `chart_env=""/具体环境` 的返回条数、占比总和与 `'其他命令'` 归并逻辑；
     - `view=ranking` 配合 `top=10/20/30/50/all` 与 `chart_env` 的排序与截断逻辑；
     - `view=versions` 配合 `chart_env` 的全量版本统计逻辑；
     - 非法 `view`/`top` 返回 `400`，未登录返回 `401`；
     - 单环境筛选后生成的下钻 `href` 携带 `environment=<chart_env>` 且跳转到 `/admin/calls` 条数精确一致；
     - 无数据环境返回 `total: 0, items: []`；
     - MySQL `Decimal` 与空集 `None` 模拟下接口 JSON 与模板 `tojson` 均返回整型数值。
2. **前端与语法校验**：
   - `node --check access-service/app/static/analytics.js`
   - `node --test access-service/tests/test_chart_scale.cjs access-service/tests/test_time_presets.cjs`
3. **页面交互与视觉验收**：
   - 「调用次数分布」无底部图例，饼图外侧清晰显示 `命令 (占比%)`，切换 `TOP10/20/30/50/全部` 与各环境无重叠、响应流畅；
   - 「调用次数排行」切换 `TOP命令` 与 `环境` 柱状图实时更新，超宽自动横向滚动；
   - 「版本分布」切换 `环境` 实时更新该环境版本占比；
   - 切换不同图表视图时各自下拉框选择互不干扰；
   - 正式发布前在 MySQL 环境实测有数据与空环境切换场景。

## 7. 已确认决策

| 编号 | 决策项 | 确认结论 |
| --- | --- | --- |
| D01 | 「调用次数排行」默认值 | 第 1 个下拉框 `TOP命令` 默认 `TOP10`，第 2 个下拉框 `环境` 默认 `全部`（与「调用次数分布」一致） |
| D02 | 「调用次数分布」TOP N 占比口径 | **方案 A**：超出 TOP N 的命令归并为 1 块「其他命令」，以当前范围总调用次数为分母（全部扇区合计 100%）；选择「全部」时无「其他命令」 |
| D03 | 与顶部「更多筛选 -> 环境」联动 | 当顶部全局筛选已指定具体环境（如 `prod`）时，图表下方「环境」下拉框默认锁定为该环境，避免与顶部筛选冲突 |
