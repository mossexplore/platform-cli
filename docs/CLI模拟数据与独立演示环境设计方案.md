# CLI 模拟数据与独立演示环境设计方案

状态：基于已审核方案，并纳入“mock 调用必须经过权限管理系统”的补充要求，作为本次实现和验收依据。实现与测试结果单独记录，不把设计目标写成已经通过的验证。

## 1. 背景与目标

CLI 的训练、算法、数据集、模型、服务、实验、WebStudio 和 Jupyter 功能依赖真实平台、身份和业务数据。缺少平台访问条件时，需要独立模拟环境支持开发、测试和外部录屏。

目标：使用与正式项目一致的 `ml` 命令获得关联完整、可持久化的数据；复用正式参数校验、请求构造、响应解析及输出；支持查询和写入连续流程；模拟故障不影响正式安装、配置、运行或独立构建。

模拟结果不代表真实平台业务结果。模拟训练和部署不创建 GPU 作业或 Kubernetes 资源。

## 2. 已确认约束

- 两套环境使用同名 `ml`，不用 `ml-mock` 或业务命令 `--mock` 参数。
- 不改终端标题、提示符，不在每条业务输出中加入演示标签。
- 通过 `ml context` 主动查询实际运行环境。
- mock 代码、种子、模拟身份、样例、场景和专用依赖不得进入正式 Wheel、Python 源码分发包及 Windows 联网、离线安装包。
- 正式 CLI 只保留通用运行上下文和依赖注入接口；不扫描或导入 mock。
- 沿用现有 scripts 正式打包入口；演示另设构建脚本、包名和输出目录。
- 模拟错误必须明确失败，不能回退到真实平台。
- 只模拟业务数据；权限检查、版本准入和调用记录由真实权限服务完成，不能关闭权限或在本地伪造放行。

## 3. 代码依据

| 链路 | 影响 |
| --- | --- |
| Typer 入口、Runtime | 复用业务命令；运行上下文必须早于历史记录初始化 |
| PlatformClient | HTTPX transport 可保留请求及响应解析路径 |
| AuthManager、浏览器登录 | 演示替换认证提供者，不打开真实登录页 |
| 权限检查、摘要和环境查询 | 独立 HTTP 客户端都需要覆盖，不能仅关闭权限 |
| 文件下载 | 独立客户端也必须走演示传输 |
| Ping 后台进程 | 需要明确继承启动提供者及独立状态路径 |
| WebStudio | 独立平台请求、实例选择和连接缓存都需隔离 |
| Jupyter | 实际 HTTP、WebSocket、Kernel 和终端，不伪造执行结果 |
| config、凭据、business、历史、安装标识 | 仅设置 --config 不足以隔离，需要统一状态目录 |
| setup.py、MANIFEST.in、Windows 构建脚本 | 明确包收集范围，检查最终归档和嵌套 Wheel |

实现前的命令清单约为 87 个叶子命令，另有命令组默认行为；新增 context 后根据实际命令树建立覆盖清单。未公开注册的内部函数不算公开命令。

## 4. 总体架构

```text
正式终端 → 正式 ml → 正式 CLI → 真实平台
演示终端 → 演示 bin/ml → 独立 CLI 核心 → 真实权限服务检查并记录
                                      ↓ 仅放行后
                                  模拟提供者 → 独立 SQLite 和文件
```

演示扩展依赖指定版本的 CLI 核心；正式 CLI 不依赖演示扩展。两者安装在不同 Python 环境。

演示包的 bin 目录提供同名包装入口，显式调用自己的 Python 和启动模块，避免两个包在同一环境争抢 console script。start-demo 仅设置当前子终端 PATH 和工作区，不能修改系统 PATH。校验失败直接退出，不能启动可能解析到正式 ml 的终端。

## 5. 运行上下文

```text
ml context
ml context --json
```

无须登录，不访问网络。展示实际运行模式、当前 profile、脱敏平台地址、CLI 版本与路径、配置和状态目录；演示额外展示工作区、场景、扩展版本、权限服务地址和上报账号。

“真实平台”不表示“生产环境”，模式与当前 profile 分开显示。来源必须是实际加载的运行上下文，不能仅凭环境变量中的文字、标题或目录名称推断。配置损坏应诊断失败，不能显示误导性的正常状态。JSON 输出不得混入标记或登录提示。

## 6. 故障隔离

### 安装与依赖

独立虚拟环境、独立入口、独立配置和版本。安装、升级、卸载演示环境不操作正式目录。正式入口不自动发现插件，mock 缺失或依赖冲突不参与正式启动。

### 状态与文件

演示配置、凭据、业务选择、历史、安装标识、Ping、WebStudio 缓存、数据库及工作文件分别保存。工作区必须有格式标记，管理操作检查目录归属和符号链接，初始化禁止覆盖既有目录。重置只处理管理对象，不清理外部导出文件。

### 网络

业务平台和下载使用 .mock.invalid 保留域名，由进程内传输处理，不查询 DNS。权限请求直连初始化时明确指定的真实服务，仅放行同源的 POST check、summary、environments 三个接口，禁止重定向、代理和任意服务端路径；TLS 校验沿用核心企业 CA 支持。未知业务地址和接口明确拒绝。独立下载客户端和后台进程同样不得回退真实业务网络。

本地 Jupyter 仅允许管理器登记的 127.0.0.1 地址和凭据。任意代码运行不受应用 HTTP 拦截约束；强隔离使用容器或虚拟机。同机进程仍共享内存、磁盘等资源，不宣称操作系统层面完全隔离。

## 7. 模拟请求后端

```text
参数校验 → 业务请求构造 → 模拟传输 → 路由与事务 → 持久化状态
         ← 原有输出与解析 ← 平台兼容响应 ←
```

不直接返回 CLI 排版文本。通用工厂覆盖平台、权限、下载、WebStudio 和 Ping 连接，正式默认行为保持真实客户端。

不同接口分别遵守既有契约：训练 taskInfos/jobs、算法 data.list/total、数据集 data/totalSize、模型 models、服务 services、特征集 JSON 字符串、文件二进制流。保留分页、成功码、字段类型、空值和失败语义。部分响应样例不是完整平台 schema。

未知接口返回明确未实现错误，不能用空成功响应掩盖遗漏。写入结果不明确时沿用原有不自动重试约束。

## 8. 数据模型

SQLite 事务持久化，明确 schema 版本和锁等待；多次独立 CLI 进程共享同一工作区状态。种子使用稳定 UUID、合成账号和可重复的日期，不包含生产数据。

业务实体包括合成用户、部门、租户、团队、算法、数据集和目录、训练任务与实例、模型来源、部署和资源模板、框架包、服务和日志、离线实验和试验、Swanboard 项目与指标、WebStudio。

关联闭环：数据集/算法 → 训练任务 → 实例 → 模型来源 → 部署 → 服务 → Pod/日志。列表与详情对应，修改后再次查询可见，不同 profile/业务隔离。

业务头必须从当前 business.json 的 selected.businessId 读取；团队业务 ID 与租户 ID 分开建模，queryTenantDetail 使用真实租户 ID。时间字段按接口要求使用毫秒或带时区字符串，显示遵守北京时间格式。

standard 包含足够数据触发分页；empty 覆盖空状态；large 覆盖较多记录。特征集覆盖宽表与模型两种类型。

| 训练 | 列表、实例、历史、详情、克隆、参数更新、启动、取消、软删除、日志和 YAML |

| 部署 | 模板、资源、框架、租户服务组；dry-run 无写入；发布创建模拟服务 |

## 10. 文件与导出

ZIP 必须能解压，YAML/JSON 能解析，CSV 包含可用数据。上传真实保存字节；下载使用虚拟 HTTPS 地址，不接触外部存储。保留路径校验、覆盖保护和错误行为。

模拟上传采用明确容量上限和有界读取，避免 MockTransport 将任意大文件无界缓冲。演示限制不改变正式上传容量。

## 11. WebStudio 与 Jupyter

平台管理为模拟；执行为可选的真实本地 Jupyter。支持真实 Contents API、Kernel、Notebook、WebSocket、POSIX exec 和终端，不生成假执行结果。

访问 URL 满足现有同源校验、实例路径前缀及唯一 token 要求。缓存按配置、环境、账号和业务隔离；停止实例/服务后不能继续使用失效连接。管理器只控制自己创建的进程，不能仅凭陈旧 PID 终止其他程序。

未启用本地服务时明确失败。完整远程 exec 依赖 POSIX；Windows 完整演示使用 Linux 虚拟机。Jupyter 根目录不是操作系统沙箱。

## 12. 场景与时间

standard、empty、large、expired-session、partial-failure、malformed-response。权限拒绝、授权到期和版本限制必须在真实权限服务配置，不作为本地模拟放行/拒绝场景。

支持按接口和次数注入错误。训练生命周期由逻辑时间控制，管理脚本推进时间，避免录屏等待和常驻线程。显示时间与客户端计算保持一致，不出现负时长。

管理脚本独立于 ml 命令树，负责初始化、状态、重置、时间、故障以及 Jupyter 生命周期。

## 14. 构建与分发

正式继续使用 build-release.cmd/ps1 和 build-install.cmd/ps1。显式限定包发现范围，清理受控旧构建目录，检查 Wheel、sdist、ZIP 和内嵌 Wheel，拒绝 mock 模块、专用依赖和状态文件。

演示独立构建为带 demo 的包名，包含指定 CLI Wheel、演示扩展 Wheel、启动器、管理器和按需离线依赖。正式核心 Wheel 不因演示重新注入模拟文件。联网与离线包说明 Python、OS 和架构要求。

mock 构建失败不影响正式独立出包；共享核心修改仍须正式回归通过。GitHub 自动源码归档包含仓库内开发源码，不等同于正式 Python sdist；若连仓库源码归档也要排除，需独立仓库。

## 15. 开发与录屏流程

开发：独立环境安装核心和扩展 → 初始化场景 → 正常 ml 操作 → 重置复现。

录屏：解压演示包 → 独立安装 → start-demo → ml context 核对 → 演示普通业务命令 → 关闭终端。

不改系统 PATH、终端标题或提示符。发生启动校验错误时不进入终端。

## 16. 测试策略

- 接口契约：请求方法、路径、businessid、参数、响应字段、分页、空数据和错误。
- 跨进程端到端：实际 CLI 安装与启动，不替换命令返回值；连续验证登录、读写、训练、部署、上传下载和切换。
- 隔离故障：扩展缺失、依赖错误、数据库损坏、未知路由、错误目录、外部配置、Jupyter 不可用、重置和卸载。
- 包级：源码目录之外干净安装正式/演示产物；正式不含扩展、同名入口正确、版本一致。
- Jupyter：真实 HTTP/WS、Notebook 成功/失败/超时、文件往返、exec、终端和清理。
- 回归：CLI、权限服务、Node 时区测试、差异检查；失败不得提交。

## 19. 验收标准

同名 ml、无视觉附加标记、context 准确；关联数据和写入持久化；真实文件产物；Jupyter 不伪造；mock 不修改正式状态且不回退真实业务网络；原正式打包入口兼容；正式包无 mock；支持范围、限制和测试证据明确。

## 20. 真实权限系统接入与验收

初始化必须提供 `--permission-url` 与 `--username`，没有默认的模拟权限服务。由管理员在权限系统登记两个独立环境：

| 环境名 | platform_origin | 授权 |
| --- | --- | --- |
| demo-dev | https://demo-dev.mock.invalid | 为实际演示账号分配所需权限 |
| demo-test | https://demo-test.mock.invalid | 按需分配，不能借用正式环境授权 |

保留域名仅用于权限系统的环境匹配，不需要解析或部署业务服务。授权、用户启停、授权有效期和版本策略由原权限系统维护；演示数据库不包含授权表。已有正式环境、账号授权和版本策略不得由安装器修改。演示日志以独立环境名区分，可由权限后台正常统计。

沿用 Runtime → check_access → 真实服务 → PlatformClient 链路。每次业务命令检查当前用户名、环境、平台 origin，以及当前 business.json 选中的 businessid；沿用 CLI 版本、安装标识、调用标识及脱敏完整命令。拒绝、超时、HTTP 错误、非法响应均在模拟业务操作前终止，不能复用上次放行或回退本地放行。保活探测补充真实权限检查；Jupyter 命令沿用核心权限流程。管理器的 reset、advance、fault、jupyter 启动也先经过权限服务。权限故障不阻止本地 context、帮助、状态查询、退出或停止自有 Jupyter；初始化仅创建本地工作区，不授予业务权限。

权限服务当前协议接受客户端上报用户名，不独立验证平台身份。演示登录产生的是本地业务会话，初始化和 identity 指定的是待检查账号，并非完成真实平台登录；不能将其作为身份认证或防恶意本地修改的安全边界。本次沿用现有协议，不增加管理员密码或网关密钥，也不把客户端伪装成可信网关。若需可信身份认证，应另行接入组织 SSO/服务端身份验证。

离线包表示依赖可离线安装，业务演示仍要求能访问真实权限服务。可使用既有权限系统，或由管理员在演示网络部署同一权限系统；演示包不内置自动放行权限服务器。单独权限系统部署所需数据库等不在演示 CLI 包内。

自动化测试启动仓库 access-service 的实际 FastAPI 应用和独立数据库，通过 TCP 访问，不替换权限判定函数。检查允许和拒绝记录真实落库、授权撤销立即生效、版本封禁阻止写入、未知账号拒绝、权限关闭被禁止和服务不可用时状态不变。用户实际部署地址和授权联调需在配置后执行；不访问或修改生产权限库。
