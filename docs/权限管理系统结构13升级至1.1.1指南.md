# 权限管理系统 1.0.9.1 → 1.1.1 升级指南

适用于 Linux x86_64、外部 MySQL 8.x、`docker run` 部署。示例容器名为 `cli-access`，配置目录为 `/opt/cli-access-config`。沿用原部署的网络、端口和 TLS 配置。目标产物以 [v1.1.1 Release](https://github.com/mossexplore/platform-cli/releases/tag/v1.1.1) 的附件和清单为准。

## 1. 核对现状与结构

- 旧镜像 `cli-access:1.0.9.1` 要求数据库结构 **13**。目标镜像 `cli-access:1.1.1` 要求结构 **15**。
- 迁移先将 `cli_call_logs.full_command` 扩为 `utf8mb4 LONGTEXT`，再为 `cli_version_policies` 添加可空的 JSON 列 `additional_environments`。原有命令日志、单环境策略、全部环境策略和临时例外保留原含义。
- 执行 `SELECT version FROM schema_versions;`，核对唯一记录。已经单独迁至结构 14 的部署只会增加环境列表列；更早结构先核对对应历史指南。

## 2. 演练、下载与校验

记录现有容器、镜像 ID 和摘要、网络、配置目录、MySQL 目标及关键表行数。把数据库和配置备份恢复到独立测试环境，用目标镜像演练迁移、启动、验收和回滚，记录用时和空间。下载目标镜像、`SHA256SUMS` 和 `manifest.json`，复制到同一目录。

```bash
sha256sum --ignore-missing -c SHA256SUMS
docker load -i cli-access-1.1.1-linux-amd64.tar.gz
docker image inspect --format '{{.Id}}' cli-access:1.1.1
docker image inspect --format '{{index .Config.Labels "org.opencontainers.image.revision"}}' cli-access:1.1.1
```

核对镜像 ID、源码提交、平台和清单。文件哈希、镜像配置 ID 和 GHCR 摘要分别核对。校验失败时暂停升级。

## 3. 维护窗口与最终备份

暂停权限检查入口、管理操作和其他写入来源，停止全部旧服务实例。单实例示例：

```bash
docker stop --time 30 cli-access
```

**现在完成最终数据库与配置备份。** 核对备份可读、恢复步骤可用，记录管理员、授权、日志、审计和版本策略的数量及代表值。保留原镜像、容器、实际 `service.env` 和外部数据库。确认最终备份可用后再迁移。

## 4. 迁移并切换至 1.1.1

使用目标镜像与原配置目录运行一次显式迁移。原部署指定 Docker 网络时沿用原设置。整个迁移阶段仅运行一个迁移进程。

```bash
docker run --rm \
  -v /opt/cli-access-config:/run/cli-access:ro \
  cli-access:1.1.1 python -m app.manage migrate
```

确认 `schema_versions` 恰有一行，值为 `15`。用 `SHOW FULL COLUMNS FROM cli_call_logs LIKE 'full_command';` 核对 `longtext` 类型及 `utf8mb4` 排序规则。用 `SHOW COLUMNS FROM cli_version_policies LIKE 'additional_environments';` 核对可空 JSON 列；已有记录该列应为 NULL。对照备份核对关键记录及数量。

保留停止的旧容器，使用空闲的备份名称：

```bash
docker rename cli-access cli-access-1.0.9.1-backup
```

使用原配置和已有管理员启动目标容器。单实例示例：

```bash
docker run -d \
  --name cli-access \
  --restart unless-stopped \
  -v /opt/cli-access-config:/run/cli-access:ro \
  -p 8008:8008 \
  --read-only \
  --tmpfs /tmp:size=64m,mode=1777 \
  --cap-drop ALL \
  --security-opt no-new-privileges:true \
  --log-driver local \
  --log-opt max-size=10m \
  --log-opt max-file=5 \
  cli-access:1.1.1
```

端口示例绑定所有网卡。生产部署沿用现有网络限制、反向代理和 TLS。

## 5. 验收与放行

```bash
docker inspect --format '{{.State.Health.Status}}' cli-access
docker logs --tail=200 cli-access
curl --fail --max-time 5 http://127.0.0.1:8008/cli-permission/healthz
```

核对原管理员登录、允许和拒绝检查、原有策略与例外、日志入库以及有数据的看板。使用合成数据验证长命令完整入库和同一策略对多个指定环境生效，其他环境按原策略判断。重启服务并确认只读挂载配置仍生效。验收完成后才恢复入口。

## 6. 回滚

旧镜像要求结构 13，不能直接使用结构 15。系统没有降级迁移。验收失败时保持入口关闭，停止目标容器，将最终备份恢复到独立回滚库，使用指向回滚库的原配置和保留的旧镜像重新验收。恢复备份会失去备份后新增的日志和配置，必要时先保存待补录数据。保留故障库、备份及镜像，禁止手改 `schema_versions`。
