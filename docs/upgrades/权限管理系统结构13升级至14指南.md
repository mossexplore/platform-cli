# 权限管理系统数据库结构 13 升至 14

适用于 Linux x86_64、外部 MySQL、`docker run` 部署。容器名为 `cli-access`，配置目录为 `/opt/cli-access-config`。部署时沿用现有网络和 TLS 配置。仅在取得包含结构 14 的已验证镜像和对应校验文件后执行。

## 1. 核对现状与结构

查看当前镜像和数据库版本。执行 `SELECT version FROM schema_versions;` 应返回唯一一行 `13`。本次迁移将 `cli_call_logs.full_command` 从 `TEXT` 扩为使用 `utf8mb4` 的 `LONGTEXT`，保留旧值和空值。其他表和原配置沿用现有数据。

## 2. 演练、下载与校验

记录当前镜像、网络、配置与数据库目标。将现有数据库备份恢复至独立测试库，使用目标镜像演练迁移、启动和验收，记录迁移用时及磁盘占用。将 `SOURCE_VERSION` 和 `TARGET_VERSION` 设为已核对的旧镜像与目标镜像标签，下载对应附件及 `manifest.json`、`SHA256SUMS`。

```bash
sha256sum --ignore-missing -c SHA256SUMS
docker load -i "cli-access-${TARGET_VERSION}-linux-amd64.tar.gz"
docker image inspect --format '{{.Id}}' "cli-access:${TARGET_VERSION}"
docker image inspect --format '{{index .Config.Labels "org.opencontainers.image.revision"}}' "cli-access:${TARGET_VERSION}"
```

核对平台、镜像 ID 和源码提交与 manifest 一致。校验失败时停止操作。

## 3. 维护窗口与最终备份

关闭权限检查入口，暂停管理操作和其他写入，停止所有旧实例。单实例命令如下。

```bash
docker stop --time 30 cli-access
```

停写后完成最终数据库和配置备份，核对备份可恢复，并记录调用日志数量和代表性的旧记录。保留旧容器、镜像与真实 `service.env`。确认备份后再开始迁移。

## 4. 迁移并切换

使用目标镜像、原配置目录和外部数据库运行一次显式迁移。若原部署指定 Docker 网络，沿用原设置。

```bash
docker run --rm \
  -v /opt/cli-access-config:/run/cli-access:ro \
  "cli-access:${TARGET_VERSION}" python -m app.manage migrate
```

确认 `schema_versions` 恰有一行且值为 `14`。通过 `SHOW FULL COLUMNS FROM cli_call_logs LIKE 'full_command';` 核对类型为 `longtext` 和字符集为 `utf8mb4`，比对调用日志数量和旧值。保留已停止的旧容器。

```bash
docker rename cli-access "cli-access-${SOURCE_VERSION}-backup"
```

沿用现有部署的网络、端口和 TLS 设置。单实例启动示例如下。

```bash
docker run -d \
  --name cli-access \
  --restart unless-stopped \
  -v /opt/cli-access-config:/run/cli-access:ro \
  -p 8008:8008 \
  --read-only \
  --tmpfs /tmp:size=64m,mode=1777 \
  --cap-drop ALL \
  --security-opt no-new-privileges:true \
  --log-driver local \
  --log-opt max-size=10m \
  --log-opt max-file=5 \
  "cli-access:${TARGET_VERSION}"
```

## 5. 验收与放行

```bash
docker inspect --format '{{.State.Health.Status}}' cli-access
docker logs --tail=200 cli-access
curl --fail --max-time 5 http://127.0.0.1:8008/cli-permission/healthz
```

核对管理员登录、原有授权、允许与拒绝调用的入库，以及有数据的看板。用合成参数验证超过 8192 字符的 Jupyter 命令能完整入库，并核对调用详情。权限服务验收通过后再切换 Go CLI、恢复业务入口。

## 6. 回滚

旧镜像要求结构 13，不能直接连接结构 14。没有降级迁移。验收失败时保持入口关闭并停止目标容器，将最终备份恢复至独立回滚库，使用指向该库的原配置和保留的旧镜像重新验收。恢复备份会丢失备份后的新增日志和配置变更。保持故障库、原备份和镜像以供核对，禁止手改 `schema_versions`。
