# v1.0.5.7 — CLI 与权限管理系统

CLI、Windows 安装包和权限管理系统统一为 **1.0.5.7**。本版汇总上一正式版 **v1.0.3.7** 之后的 CLI 能力，并修复人员授权页环境过多时撑宽表格的问题。附件来源、已测试镜像摘要及文件校验以 `manifest.json`、`SHA256SUMS` 为准。

## 本版变化

- 新增数据集列表、详情、目录查询和单文件追加上传；目录显示当前位置与完整路径，上传显示发送进度。
- 新增模型列表、详情、溯源及关联训练任务查询，完善模型大小、北京时间和完整 ID 展示。
- 服务日志统一使用 `ml service logs SERVICE_ID`，支持按需分页选择主机、日志类别及文件，支持非交互目标参数；移除旧 `ml service host logs` 命令入口。
- 新增 Jupyter 远端文件操作及非交互程序执行；Web Studio 连接缓存默认一小时，可按配置关闭或显式刷新。在线权限检查继续逐条执行，写入操作不自动重放。
- 登录状态增加平台活动续期及终端会话自动保活；业务选择可逐级返回或取消，支持部门搜索；训练任务克隆使用当前用户作为创建人。
- 新增 `ml history` 与 `ml history list`，交互终端每页浏览 20 条，非交互默认输出最近 20 条；支持筛选、JSON 输出和 `ml history clear`。脱敏后的历史保存在本地文本中，最多保留 1000 条；`--no-history` 或 `ML_HISTORY=0` 可禁用自动记录。
- 命令树说明统一去除末尾标点；移除表格多余时区脚注，数据集目录以黄色显示。
- 人员授权页按环境列可用宽度尽可能显示完整标签，放不下时显示“展开全部（总数）”；支持收起、随列宽重新计算及长名称展开换行，不改变授权规则。

## 使用前提与兼容性

业务命令需配置当前环境、登录并选择业务，同时通过现有权限服务检查。新增模型、数据集等请求使用当前环境地址和所选业务；帮助、本地历史查询及清理无需联网。

升级前备份 CLI 用户配置，安装后核对平台地址及权限服务地址；安装器会更新默认配置，保留自动保活开关和间隔。Web Studio 缓存包含短期凭据，不应分享；历史只存脱敏命令和执行结果，不存输出或文件内容，也不自动重新执行。旧服务日志脚本须改用 `ml service logs`；模型详情和溯源要求平台响应明确返回成功状态。

## 数据库升级与回滚

已逐文件比较 v1.0.3.7 与目标源码的 `access-service/app/migrations.py` 和 `models.py`，两者均无变化，数据库结构仍为 **10**。现有结构 10 且数据、管理员正常时**不运行迁移、不重新创建管理员**。更早结构必须先按真实 schema 及历史指南制定升级方案，不能手改结构版本。

在独立库演练备份恢复；维护窗口停止全部旧实例和写入后完成最终数据库及配置备份，再保留旧容器、替换镜像。验收健康、登录、授权允许/拒绝、日志、有数据的数据看板及人员授权页环境展开后放行。保留原 `service.env`、外部 MySQL 和旧镜像；无结构变化时可用旧镜像连接原结构 10 库回滚。本版无降级迁移；恢复备份会丢失备份后新增的日志、审计和配置变更。完整分步操作见 `Docker-upgrade-1.0.5.7.md`。

## 验证范围与限制

正式工作流门禁包括 CLI 与权限服务测试、浏览器时区与环境标签折叠逻辑测试；Windows 联网和禁止访问包源的离线安装、重复安装及从正式 CLI 1.0.3.7 升级；linux/amd64 同一候选镜像在 MySQL 8 中的健康、管理员登录、授权允许/拒绝、日志持久化、有数据的数据看板数字 JSON、重启和目录挂载配置更新；镜像来源证明、Docker save/load 往返与离线附件组装。发布前下载草稿，独立核对哈希、Wheel、Windows 包、镜像身份及文档。

真实业务平台、远端 Web Studio/Jupyter、生产 MySQL 及真实浏览器视觉验收不在本次自动验证范围内。数据集上传尚未验证真实 2GB 文件、同名覆盖及压缩包处理，当前采用 2,000,000,000 字节上限；超时后须查询核实，避免重复上传。历史记录在强制终止或断电时可能缺少最后一条。部署方仍须按指南完成环境验收。

GitHub Release 不会自动部署生产、迁移数据库或修改业务版本准入策略。
