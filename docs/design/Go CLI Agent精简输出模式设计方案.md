# Go CLI Agent 精简输出模式设计方案

## 1. 目标与首期范围

拟新增全局布尔参数 `--agent`，让 Agent 以较小的 JSON 响应完成查询和后续操作。部分列表的现有 JSON 保留整条后端记录，部分命令还保留响应包络；两者均有精简空间。首期按字段选择压缩体积，完整返回所请求页面的记录，暂不设 Token 硬上限。

**首期一次性交付整棵 Go CLI 命令树。** 以 [Go CLI 命令注册入口](../../cli-go/internal/command/command.go) 为准，覆盖所有叶子命令、可直接执行的分组（如 `ml business TENANT_ID`）、按配置注册的 KB 命令，以及根级帮助、版本和补全入口。WiseRec 与 MLOps 各自在原有平台和权限范围内执行。

全量覆盖按命令实际交付物验收：业务查询返回机器可读结果，文件操作返回操作结果并保留目标文件，交互终端和宿主协议沿用各自的数据流。第 4 节给出全量适配要求，第 5 节的三条查询用于验证跨命令工作流。

## 2. 参数、优先级与宿主兼容

`--agent` 可放在子命令前后。环境变量仅在值为 `1` 时启用默认精简模式。以下规则在业务鉴权和命令操作前统一判定，显式格式选项须为该命令原本支持的选项。

| 条件（按顺序判定） | 结果 |
| --- | --- |
| 显式 `--agent` 或 `--agent=true`，同时显式传入 `-o`、`--output` 或 `--json` | 用法错误，退出码 2，stderr 说明选项互斥 |
| 显式启用 `--agent` | 所有命令进入第 4 节对应的输出策略，业务命令输出紧凑 JSON，协议与交互入口使用约定的数据流 |
| 显式 `--agent=false` | 覆盖环境变量，按命令原有格式规则执行，可与原有格式选项同传 |
| 仅显式指定原有格式选项 | 即使设置了 `ML_AGENT=1`，也按显式选项执行 |
| 仅设置 `ML_AGENT=1` | 按显式启用时的同一策略执行，包括宿主协议的透传规则 |
| 以上均不满足 | 沿用命令默认值及环境配置中的输出偏好 |

兼容检查须覆盖根参数前置的命令发现。[KB 注册逻辑](../../cli-go/internal/command/command.go) 当前先看第一个参数，实施时需识别前置全局选项。启用 KB 的环境里，`ml --agent kb file list` 和后置写法应执行同一查询并输出等价的精简 JSON；`ml --agent=false kb file list` 应能正常进入原命令。

[DSH 插件](../../dsh-plugin/wiserec-cli/runner.js) 读取 `ml context --json`，并调用 `ml auth ping tick --capabilities` 和 `ml auth ping tick --json`。三条调用均按原协议验证，其中能力探测没有显式格式参数。宿主是否默认注入环境变量，在首期兼容与收益验收后决定。

## 3. 列表输出契约

### 字段选择与值类型

各命令用现有表格列确定候选字段，再按后续操作补充机器字段。[表格格式化函数](../../cli-go/internal/command/train_output.go) 返回展示字符串，可能舍入大小、合并单位或用短横线表示空值。Agent 投影应从原始记录提取类型化值。

- ID、名称、路径、枚举代码和后续命令所需参数使用完整值。数值和布尔字段保持 JSON 数值和布尔类型。时长、文件大小在字段说明中注明源单位；时间转换到北京时间，以 `YYYY-MM-DD HH:mm:ss` 展示。组合列的字典和条目使用各个源字段，例如服务部署列表分别保留镜像名和版本。训练实例缺少 `runningTime` 时，仅对具有有效开始时间的运行中实例补算整分钟数。
- 可选描述字段按原始值判断是否省略。保留 `0`、`false`、字面字符串 `"-"` 和有业务含义的空集合。跨租户查询保留每条记录自身的 `businessId`；响应缺失时不得拿当前选中业务补值。请求头继续使用当前环境生效的业务选择。
- 截断采用逐字段白名单，初始条目为数据集列表的 `description`。超过 256 个 Unicode 码点时返回前 256 个，在该记录的 `_truncated` 对象中以字段名记录原长度，例如 `{"description":830}`。完整描述可用相同筛选和页码显式指定 `-o json` 获取。
- Agent 列表在顶层返回一次 `fields` 字典，将条目字段映射到中文说明，适用时注明单位。列表为空时仍返回字典。嵌套字段使用点号路径，例如 `roleJobInfo.plogReady`。条目继续使用原字段名和类型。

### 页范围与总数

每个列表返回单个 JSON 对象，`items` 始终是数组，保留服务端顺序和条数。以下字段区分“拿到多少条”和“还能怎么查”。

| 字段 | 含义 |
| --- | --- |
| `fields` | 条目字段说明字典，整次响应返回一次 |
| `returnedCount` | 本次返回的条数，等于 `items` 长度 |
| `total` | 服务端明确给出的匹配总数，包括 0。接口允许缺省时省略；接口要求总数而响应缺失时沿用原错误 |
| `pagination` | `paged` 表示可传页码，`fixedFirstPage` 表示 CLI 只提供固定首页，`unpaged` 表示完整无分页列表，`limited` 表示按命令上限返回的记录（如历史记录的 `--limit`） |
| `pageIndex`、`pageSize` | 分页和固定首页均给出查询页码及容量。训练看板实验列表的接口未给出容量时，`pageSize` 为 `null`。无分页或按上限读取时省略这两项 |

例如，服务主机查询匹配了 23 条、只取到 10 条时，输出应同时包含 `"returnedCount":10`、`"total":23`、`"pagination":"fixedFirstPage"`、`"pageIndex":1` 和 `"pageSize":10`。Agent 可报告首页范围或使用命令支持的 Pod IP 筛选。下面以只有 `id` 和 `name` 两个投影字段的可翻页列表为例。

```json
{"pagination":"paged","pageIndex":1,"pageSize":10,"returnedCount":0,"total":0,"fields":{"id":"资源 ID","name":"名称"},"items":[]}
```

### 命令特有字段

| 命令 | 投影要求 |
| --- | --- |
| `dataset list` | 从现有列提取 `dataSetId`、`dataSetName`、`businessId`、类型、修改者、大小、时间、区域、存储桶和描述。数值大小与精确 ID 必须可用于后续处理 |
| `service host list` | 保留 `nodeName`（Pod 名称）、`clusterName`、`nodeHost`（Pod IP）、`hostIp`（主机 IP）、健康状态代码、规格、并发与超时等主机列；时间和利用率按字段语义处理 |
| `train history list` | 在现有作业列外保留 `jobType`。普通作业在记录上给出 `plogReady`；`dps-train` 保留 `roleJobInfo` 中每个角色的 `roleJobId`、`roleType`、原始 `status` 和自己的 `plogReady`。使用下载逻辑的 `platform.HasPlog` 对相应记录判断；布尔值表示当前 CLI 能否确认该目标已有 plog |

## 4. 全量命令如何输出

以下各行共同构成首期范围。一个命令可因调用方式产生不同交付物，例如 `service host log-search --list` 返回文件列表，读取日志时返回正文。

| 命令入口与范围 | Agent 模式的输出与执行要求 |
| --- | --- |
| `context`、`env`、`business`、`user`、`access`、`history`、`login`、`logout`、`auth` | 状态输出当前生效环境、业务及相关状态；列表保留选择所需标识。登录、切换、刷新、清理与保活操作输出实际结果。保留凭据显示条件、历史脱敏和交互确认；`auth ping tick` 走下述协议策略 |
| `dataset`、`featureset`、`feature-task`、`quality`、`sample-task` | 列表保留筛选和分页范围，以及下游查询所需 ID；详情保留关联字段。特征集配置紧凑编码并完整保留嵌套结构、空集合和 null；日志保留请求范围内正文；文件上传和 CSV 导出返回实际目标及结果，数据集上传以 `accepted` 表示平台已受理请求 |
| `train`、`mtp swanboard`、`offline` | 训练列表、历史及详情保留作业和角色标识。看板保留项目、空间、实验标识和指标数值。启动、取消、删除、克隆、配置更新与导出按操作返回结果；归档下载保留逐项状态、失败原因和落盘路径；试运行返回预览 |
| `model`、`resource`、`deployment`、`algorithm`、`service` | 模型溯源以模型 ID 为入口，模板查询保留部署所需 ID；部署预览和提交结果分别编码。算法仓下载和克隆返回实际路径或新资源标识。服务视图区分固定首页和未知总数，Pod 事件保留次数和时间，日志保留容器状态与正文，mock 保留逐节点结果和整体退出状态 |
| `webstudio`、`jupyter` | 实例查询与切换保留实例 ID。文件操作保留路径和结果，按行读取时保留所选正文。exec 保留 stdout、stderr、截断状态和远端退出状态；Notebook 运行保留部分执行结果及产物位置。终端 list、close 输出结构化结果，open、attach 走交互流 |
| `kb` | 启用 KB 时适配知识库、页面、搜索、原文件列表及下载。保留资源标识、来源、页范围和下载目标；沿用查询准入和审计 |
| `tree`、根命令与分组帮助、版本、Shell 补全 | `tree` 输出结构化命令树，保留平台支持信息及原有可见范围。帮助和版本使用原生文本；补全脚本与补全候选使用 Shell 约定的格式；安装补全返回操作结果 |

**输出边界。** 结构化命令成功时向 stdout 写入一个紧凑 JSON 值和末尾换行，进度、提示、诊断写入 stderr。交互式选择按原有条件从 stdin 读取；Agent 模式不会代替用户确认或自动添加 `--yes`。对下载、上传、部署、删除等命令，测试须比较操作次数、目标及落盘内容。终端 open、attach 透传终端数据；宿主 tick 与能力探测保留协议字段与输入输出约定。帮助、补全和终端流不能经过通用 JSON 编码器。

**错误与部分结果。** 校验业务响应后再投影。用法错误、权限拒绝和失败沿用命令退出码；原本会返回结构化失败或部分结果的路径仍输出可解析的结果。Jupyter exec 保留 0 至 255 范围内的子进程退出码、超时 124 和中断 130，使用结果中的 `status` 区分子进程失败、超时和中断；服务 mock 有节点失败时仍输出所有节点的结果并报告整体失败。版本准入拒绝时，Agent 模式直接给出诊断，避免升级提示等待输入。

**实现入口。** 在命令层解析全局模式，按命令路径及实际操作选择投影、执行摘要或原生协议。[公共查询入口](../../cli-go/internal/command/catalog_query.go) 在完成响应与分页校验后调用共享渲染；训练、KB、Jupyter、本地状态和写操作从各自的结果对象接入。在 `internal/output` 集中处理分页对象和紧凑编码；现有 `output.JSON` 继续服务原格式。请求、鉴权、写入和审计复用现有执行路径。新增模块遵守仓库的单模块行数规范。

## 5. 首期验收

**覆盖门禁。** 从实际 Cobra 注册树枚举每条可执行路径，包含有子命令的可执行分组，分别检查 KB 启用与关闭、WiseRec 与 MLOps 的可见性和限制。每条路径登记输出策略、调用样例、预期 stdout/stderr、退出码和副作用；对改变交付物的选项另列用例。将注册路径与契约用例双向比对，缺失或失效的条目均须在首期补齐。通过真实命令入口运行测试，业务请求用模拟服务，写文件使用临时目录。

以下是逐命令覆盖之外的代表性验收场景。

| 场景 | 操作与断言 |
| --- | --- |
| 数据集分页 | 执行 `ml dataset list --name NAME --page 2 --page-size 10 --agent`，比较同请求普通 JSON 的记录顺序、条数和 ID。增加空页、总数为零、长中文描述和 0 字节样例；用跨租户同名数据验证选择准确且原鉴权生效 |
| 服务主机固定首页 | 执行 `ml service host list SERVICE_ID --agent`，构造总数 23、返回 10 条，断言固定首页及各计数。从同一条记录取 Pod 名和集群名，组装 `ml service host pod-event --pod POD_NAME --cluster-name CLUSTER_NAME`。另测主机接口缺少必需总数时报错；用允许缺总数的服务部署样例验证共享分页编码省略 total |
| 训练日志串联 | 执行 `ml train history list TASK_ID --latest-flag all --agent`。构造同一作业两个角色仅一个 plog 就绪，通过目标角色的标识和布尔值组装 `ml train history logs download TASK_ID JOB_ID --role-job-id ROLE_JOB_ID --type plog`。同时覆盖普通作业和未就绪角色，全程从列表定位 |
| 参数、错误与兼容 | 验证第 2 节各组合，覆盖参数前后置、KB 开关和三条 DSH 调用。冲突返回 2 且无业务请求，已有输出模式继续通过回归测试。精简查询遇到业务异常、权限拒绝或旧版本拒绝时检查退出码、stdout、stderr 和有无交互 |
| 配置、正文与协议 | 对特征集配置做 JSON 深比较，覆盖空集合、null 和嵌套对象；比较文件读取的指定行、下载文件的字节内容；验证帮助、版本、补全及交互终端流可由原消费者读取 |
| 写操作、部分失败与退出码 | 对模型部署预览、提交、用户取消分别断言请求次数和结果；构造批量下载部分失败、mock 节点失败及 Jupyter 超时、中断，核对 stdout 中的结果、stderr 诊断和进程退出码 |

## 6. 收益评估与实施交付

使用模拟 HTTP 服务向真实 CLI 命令入口提供合成数据集和分布式作业响应。普通 JSON 和带 `fields` 的 Agent JSON 直接取自 stdout；对普通 JSON 去缩进，对 Agent JSON 移除字典，分别得到另外两组输出。下表统计 UTF-8 字节数和文本 Token 数，包含末尾换行。分词采用 GPT-4o 的 `o200k_base`，工具为 `tiktoken 0.12.0`。

| 样本 | 普通 JSON | 仅去缩进 | 字段投影 | 字段投影加字典 |
| --- | ---: | ---: | ---: | ---: |
| 数据集空页 | 68 / 30 | 51 / 18 | 90 / 27 | 485 / 125 |
| 数据集单条 | 679 / 217 | 475 / 147 | 391 / 122 | 786 / 220 |
| 数据集满页（10 条） | 6,188 / 1,891 | 4,328 / 1,308 | 3,138 / 977 | 3,533 / 1,075 |
| 数据集长描述 | 3,757 / 882 | 3,553 / 813 | 1,166 / 289 | 1,561 / 387 |
| 单条分布式作业（2 个角色） | 907 / 232 | 558 / 149 | 334 / 98 | 1,323 / 358 |

相比普通 JSON，带字典的满页和长描述样本分别节省约 43% 和 56% 的 Token。空页、单条和分布式角色样本分别多用 95、3 和 126 个 Token。样本展示字典的固定开销，结果以实际页大小和记录内容为准。

实施首期功能时，运行 Go CLI 回归测试，检查真实帮助与命令树，并同步更新使用手册、Skill 入口、相关操作指引及命令速查模板。运行 `python scripts/sync_skill_index.py` 生成速查表，再用 `--check` 校验。手册与 Skill 按全量命令范围同步使用前提、参数、示例、输出含义和副作用。公共渲染、各命令接入、宿主回归可分步开发；首期交付以全量覆盖门禁通过为准。
