# 权限管理系统数据看板新增「版本分布」与「调用环境情况」图表设计方案

> 文档状态：已确认并进入开发实施
>
> 适用模块：`access-service`（权限管理系统数据看板 `/cli-permission/admin/analytics`）

---

## 1. 背景与目标

当前权限管理系统数据看板的「数据分析」卡片已提供 4 个可视化视图：

1. **命令分布**（按时间粒度的命令堆叠柱状图）
2. **调用趋势**（按时间粒度的检查次数/通过/拒绝折线图）
3. **调用次数分布**（命令调用占比环形饼图）
4. **调用次数排行**（Top 10 命令柱状图）

为帮助管理员直观掌握客户端升级覆盖情况与各环境使用热度，本次在「数据分析」卡片中新增 2 个视图：

1. **版本分布**：与「调用次数分布」视觉风格一致的环形饼图，统计所选范围内调用记录的 CLI 版本分布；**不在底部图例中展示**，而是**直接在饼图上标注具体版本号与占比**。
2. **调用环境情况**：与「调用次数排行」视觉风格一致的柱状图，统计所选范围内每个环境的调用次数，**横坐标为环境标识，纵坐标为次数**。

本次改造仅涉及权限系统后端聚合查询与前端自研 SVG 图表渲染，**不涉及数据库表结构变更或数据迁移**，不引入任何外部 CDN 或第三方前端图表库。

## 2. 现有基础与数据来源核对

基于当前仓库 `access-service` 代码核对结果：

| 核对项 | 现状 | 设计结论 |
| --- | --- | --- |
| 数据来源表 | `cli_call_logs`（模型 `CallLog`，见 `access-service/app/models.py`） | 直接复用现有筛选条件 `filters` 进行分组聚合 |
| CLI 版本字段 | `CallLog.cli_version`（`String(64)`，默认 `'1.0.0'`） | 已有字段，无需迁移；防御性处理空值为 `'未知版本'` |
| 环境标识字段 | `CallLog.environment`（`String(64)`，已有索引） | 存储即环境标识（如 `prod`、`test`），无需联表取中文名 |
| 调用日志下钻 | `/cli-permission/admin/calls` 已原生支持 `cli_version` 与 `environment` 精确筛选 | 点击饼图扇区或柱子可直接下钻至对应调用日志 |
| 统计口径 | 遵循数据看板现有筛选条件（时间范围、环境、用户名、业务 ID、CLI 版本） | 两个新图与现有 4 个图保持同一统计范围与数据一致性 |
| 数值序列化 | `analytics.py` 使用 `count_value()` 将数据库聚合结果统一转为 Python `int` | 严格沿用，防止 MySQL 返回 `Decimal` 或 `None` 导致 `tojson` 报错 |

## 3. 详细设计

### 3.1 页面交互与视图切换

在 `access-service/app/templates/analytics.html` 的 `.analytics-view-switch` 中依次追加两个视图按钮：

| 顺序 | 按钮文案 | `data-analysis-view` | 副标题说明（`data-analysis-description`） |
| --- | --- | --- | --- |
| 1 | 命令分布 | `commands` | 按{粒度}查看各命令的调用分布 |
| 2 | 调用趋势 | `trend` | 按{粒度}查看授权检查、通过与拒绝的变化 |
| 3 | 调用次数分布 | `distribution` | 所选时段内各命令的调用次数占比 |
| 4 | 调用次数排行 | `ranking` | 所选时段内调用次数最多的命令 |
| **5（新增）** | **版本分布** | **`versions`** | **所选时段内各 CLI 版本的调用次数占比** |
| **6（新增）** | **调用环境情况** | **`environments`** | **所选时段内各环境的调用次数** |

响应式适配：
- 桌面端 `.analytics-view-switch` 保持 Flex 横排并在空间不足时自动换行；
- 移动端（`<= 520px`）已有 `grid-template-columns: repeat(2, minmax(0, 1fr))`，6 个按钮刚好排成整齐的 3 行 × 2 列。

### 3.2 图表一：版本分布（环形饼图 + 图内标注）

#### 3.2.1 后端聚合逻辑（`access-service/app/analytics.py`）

1. **查询语句**：复用现有 `top_rows(db, filters, CallLog.cli_version, limit=None)`，按 `COUNT(*) DESC, cli_version ASC` 排序。
2. **切片展示规则（已确认：全量）**：
   - 展示当前筛选范围内**全部有调用记录的 CLI 版本**，不合并为 `'其他版本'`。
3. **空值与下钻链接**：
   - 若记录中 `cli_version` 为空字符串或 `None`，显示名称兜底为 `'未知版本'`，`href` 置为 `''`（避免跳转到空参数查询）；
   - 正常版本 `ver` 的 `href` 使用 `log_link(params, start, stop, cli_version=ver)`，保留当前时间范围及其他筛选条件。
4. **类型安全**：
   - 所有 `value` 经 `count_value()` 转为原生 `int`；
   - 输出字段挂在 `chart['versions']`，结构与 `chart['distribution']` 完全一致：
     ```json
     [
       {"label": "1.0.9.6", "value": 120, "href": "/cli-permission/admin/calls?...&cli_version=1.0.9.6"},
       {"label": "1.0.9.5", "value": 45, "href": "/cli-permission/admin/calls?...&cli_version=1.0.9.5"},
       {"label": "1.0.9.4", "value": 15, "href": "/cli-permission/admin/calls?...&cli_version=1.0.9.4"}
     ]
     ```

#### 3.2.2 前端 SVG 渲染设计（`access-service/app/static/analytics.js`）

1. **环形主体复用**：
   - 沿用「调用次数分布」的环形饼图结构，前 5 个主色沿用现有色板（`#0052d9`、`#00a870`、`#7b61c9`、`#ed7b2f`、`#df658b`），并扩展多色色板以支持全量多版本循环着色；
   - 环心继续居中展示总次数 `total` 及副文案 `次授权检查`。
2. **图内标注替代图例（已确认格式：`版本号 (占比%)`）**：
   - 切换到 `versions` 视图时，**清空并隐藏底部图例容器**（`legend.replaceChildren(); legend.hidden = true`），切换到其他视图时恢复 `legend.hidden = false`；
   - 在饼图外围使用 **引导线（Leader Line）+ 外部标注文字** 直接展示每个切片的 **版本号与占比**，格式固定为 `版本号 (占比%)`，例如 `1.0.9.6 (42.5%)`（占比保留 1 位小数，与现有统计口径一致）。
   - 采用外侧引导线标注而非压在色环内部的原因：版本号加占比宽度约 100–130px，色环宽度仅 42–46px，小占比扇区无法在环内清晰排布；外侧引导线可确保大小扇区均清晰可读且视觉整洁。
3. **防重叠排布与高度自适应策略**：
   - 按每个扇区的中心角 $\theta$（从 12 点方向 `-90°` 顺时针累加）划分左、右两侧（$\cos\theta \ge 0$ 放右侧，$\cos\theta < 0$ 放左侧）；
   - 当全量版本较多时，画布高度按单侧最大标注数动态扩展（`Math.max(340, maxSideCount * 22 + 44)`），环心自动垂直居中，保证所有版本标注均有充足排布空间；
   - 单侧标注按理论纵坐标排序后执行双向垂直避让（最小行距 `22px`，并限制在画布上下边距内），避免相邻小扇区文字重叠；
   - 引导线采用两段折线：由环外缘出发沿径向引出至拐点，再水平延伸至文字起点，颜色与对应扇区一致，末端对齐文字。
4. **边界场景处理**：
   - **仅 1 个版本（100%）**：完整绘制闭合圆环（不留 `2px` 缺口），引导线默认从 3 点钟方向水平引出，标注 `<版本号> (100.0%)`；
   - **窄屏适配**：画布最小宽度设为 `Math.max(640, graphic.clientWidth)`，为左右两侧标注预留充足空间；屏幕宽度不足时自动触发外层 `.analytics-plot-scroll` 横向滚动并显示“左右滑动可查看完整图表”提示；
   - **长版本号截断**：单侧标注文本超过可用宽度时仅截断版本号部分并保留 ` (占比%)`，完整版本号与精确次数通过 SVG `<title>` 悬停提示展示（`${item.label}：${item.value} 次（${pct}%）`）。
5. **交互一致**：
   - 扇区与对应外部标注包裹在同一 `<a href>`（或无链接时 `<g>`）内，悬停高亮、提示完整信息，点击下钻到对应版本的调用日志。

### 3.3 图表二：调用环境情况（柱状图）

#### 3.3.1 后端聚合逻辑（`access-service/app/analytics.py`）

1. **查询语句**：按 `CallLog.environment` 分组聚合，统计每个环境的调用次数：
   ```python
   rows = db.execute(
       select(CallLog.environment, func.count().label('total'))
       .where(*filters)
       .group_by(CallLog.environment)
       .order_by(func.count().desc(), CallLog.environment)
   ).all()
   ```
2. **展示数量**：
   - 展示当前筛选范围内**全部有调用记录的环境**（不人为截断为 Top 10），按调用次数从高到低排列，次数相同时按环境标识字典序稳定排序。
3. **空值与下钻链接**：
   - `label` 直接取环境标识 `name`（空值兜底 `'未知环境'`）；
   - 非空环境生成下钻链接 `log_link(params, start, stop, environment=name)`，点击柱子直接查看该环境在当前时段内的调用日志。
4. **类型安全**：
   - 经 `count_value()` 转为原生 `int`；
   - 输出字段挂在 `chart['environments']`：
     ```json
     [
       {"label": "prod", "value": 150, "href": "/cli-permission/admin/calls?...&environment=prod"},
       {"label": "test", "value": 30, "href": "/cli-permission/admin/calls?...&environment=test"}
     ]
     ```

#### 3.3.2 前端 SVG 渲染设计（`access-service/app/static/analytics.js`）

1. **复用柱状图渲染逻辑**：
   - 将现有 `rankingBars()` 抽离为通用分类柱状图渲染函数 `categoryBars(items, {xAxisLabel, legendLabel})`：
     - **调用次数排行（`ranking`）**：`items = data.ranking`，横坐标标题 `'命令名称'`，纵坐标标题 `'次数'`，图例 `['按命令汇总的授权检查次数']`；
     - **调用环境情况（`environments`）**：`items = data.environments`，横坐标标题 `'环境标识'`，纵坐标标题 `'次数'`，图例 `['按环境汇总的授权检查次数']`。
2. **视觉与交互完全对齐**：
   - 复用 `countScale()` 生成整数且不重复的纵坐标刻度；
   - 柱体样式、圆角（`rx: 4`）、品牌主色（`#0052d9`）、柱顶数值标注（`analysis-rank-value`）、横坐标等宽字体与长标识换行/省略截断逻辑均与「调用次数排行」完全一致；
   - 环境数量较多时，画布宽度按 `Math.max(560, graphic.clientWidth, items.length * 130 + 70)` 自动扩展并支持横向滚动；
   - 悬停提示 `${item.label}：${item.value} 次`，点击柱子或横坐标标识直接下钻调用日志。

## 5. 测试与验收计划

### 5.1 自动化测试

1. **后端统计与边界测试**（`PYTHONPATH=access-service python -m pytest access-service/tests -q`）：
   - 验证版本分布按次数降序、版本号字典序稳定排列，且全量返回所有有调用记录的 CLI 版本（不合并为 `'其他版本'`）；
   - 验证调用环境情况返回所有有记录的环境、按次数降序且同次数按环境标识稳定排序；
   - 验证顶部筛选条件（时间范围、环境、用户名、业务 ID、CLI 版本）对两个新图同样生效；
   - 验证点击下钻链接（`cli_version=...`、`environment=...`）打开 `/cli-permission/admin/calls` 后的条数与图表数值精确一致，空值不生成错误链接；
   - 验证特殊字符（如 `<script>`）在版本号或环境标识中经过安全转义；
   - **MySQL 聚合类型回归**：模拟 MySQL 返回 `Decimal` 与空集 `None`，验证 `analytics.html` 中 `chart|tojson` 渲染成功且 `chart['versions']`、`chart['environments']` 中所有 `value` 严格为 Python `int`。
2. **既有前端测试**：
   - 运行 `node --test access-service/tests/test_chart_scale.cjs` 确保刻度计算无回归。

### 5.2 页面视觉与交互验收

1. **版本分布**：
   - 1 个版本（100%）、3 个版本、6+ 个版本（含占比 1%–3% 的相邻小扇区）场景下，版本号与占比以 `版本号 (占比%)` 格式清晰显示在饼图外侧，无重叠、无截断错位；
   - 底部图例区域不显示；
   - 鼠标悬停显示精确次数与占比，点击正常版本扇区/标注可跳转调用日志。
2. **调用环境情况**：
   - 1 个环境、多环境场景下，柱状图风格与「调用次数排行」一致，横坐标显示环境标识且轴标题为「环境标识」，纵坐标轴标题为「次数」且刻度为整数；
   - 点击柱子可跳转对应环境的调用日志。
3. **MySQL 环境实测**：
   - 正式发布前在 MySQL 环境访问含真实数据的数据看板，确认页面返回 `200` 且 6 个视图均可正常切换渲染。

## 6. 已确认决策

| 编号 | 决策项 | 确认结论 |
| --- | --- | --- |
| D01 | 版本分布切片数量 | **全量展示**：展示所选范围内全部有调用记录的 CLI 版本，不合并为「其他版本」 |
| D02 | 版本分布图内标注格式 | **`版本号 (占比%)`**：例如 `1.0.9.6 (42.5%)`，通过饼图外侧引导线标注，隐藏底部图例；悬停提示展示精确次数与占比 |
| D03 | 调用环境情况展示范围 | **全量展示**：默认展示所选范围内全部有调用记录的环境（不截断 Top 10，环境较多时自动横向滚动） |
