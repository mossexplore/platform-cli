# 权限通知开发与验收说明

日期：2026-10-22（北京时间）。这是开发交付说明，不是正式版本发布或生产升级指南。

## 交付位置

- 权限服务：当前项目 `access-service/app/notification_*.py` 与 `templates/notifications.html`。
- 独立助手：独立子项目 `permission-notifier/`；依赖、源码、网页、托盘、Windows 安装脚本及测试独立管理。
- 设计基线：[权限申请通知与独立本地助手设计](权限申请通知与独立本地助手设计.md)。

助手项目没有添加到 CLI 源码或依赖中。不增加 `ml` 命令，不修改 CLI 根配置和 skill；独立助手没有远程发布或上传到公共包仓库。

## 开发环境启用顺序

1. 在开发数据库执行现有权限服务迁移入口，使结构达到 12。结构 11 → 12 新增 `notification_clients` 和 `notification_tasks`，初始化唯一客户端为关闭状态，保留既有申请、管理员和授权。
2. 服务端环境配置 `NOTIFICATION_OWNER_ADMIN_ID` 为现有管理员数字 ID。可由有权限的运维在数据库只读查询 `SELECT id, username FROM admins` 确认；默认值 0 不开放个人通知页面。
3. 重启开发服务，所有者登录后进入“个人通知”，开启事件生成，生成一次性 Token。
4. 按独立助手 README 安装，在 `http://127.0.0.1:18765` 配置并绑定，选择真实消息接口成功规则后主动测试。
5. 通过申请页面提交测试申请，查看逐对象发送与服务端任务摘要。没有用户授权时，不向真实接收人发送测试消息。

Token 由权限系统发放，auth 由消息接口提供，两者不能混用。真实 URL、auth、UID 只填写到用户电脑，不写入项目。

## 与设计基线的具体化

- 新增机器接口 `POST /api/v1/notifications/check`，用于不改变心跳状态的凭据检查。
- 成功判据默认 `unconfirmed`；支持显式确认 HTTP 2xx 接受，或 JSON 字段与指定 JSON 值严格相等。没有假定未知业务 code，不把接受成功描述成实际送达。
- 未提供幂等/查询契约，因此当前不自动重发不确定项，也不向第三方私自添加幂等字段。将来确认契约后再扩展适配器。
- 业务错误码未提供，当前仅把连接尚未建立等明确情形列为自动重试；HTTP 401/403 暂停共享认证通道，其他未知业务结果保守进入不确定状态。
- 两张服务端表保存匿名 delivery_id 和状态，真实 UID 快照仅在本地 JSON 中；服务端提供针对明确失败项的重试意图，不构造接收列表。
- 文本文件采用 config_revision 防止页面旧表单覆盖配置，统一锁与原子替换防止状态丢失；延后服务地址切换时暂存旧有效连接，清理后不积累历史凭据。
- 消息接口变化后，未完成旧快照需显式迁移；不确定项必须先处理。服务地址切换须完成或显式处置旧任务，可重新保存旧地址取消切换。
- 由于当前是单用户模式，Token 权限校验与任务写操作在唯一客户端行上串行化，同时适配 SQLite 测试与 MySQL；不会在数据库事务内发送消息。
- 默认联网安装，需要 Windows Python 3.12；未把 Python 解释器或离线依赖伪装为已经打包。

## 验证入口

```bash
# 权限服务全部回归
PYTHONPATH=access-service .venv/bin/python -m pytest access-service/tests -q

# CLI 回归、打包隔离
.venv/bin/python -m pytest tests -q

# 独立助手及跨项目模拟联调（在助手项目目录执行）
PERMISSION_SERVICE_SOURCE=/workspace/platform-cli/access-service /workspace/platform-cli/.venv/bin/python -m pytest -q
```

MySQL 用例为 `access-service/tests/test_notification_mysql.py`，仅接受显式配置的 `NOTIFIER_TEST_DATABASE_URL`，且数据库名必须是 `notification_test`。只能指向临时测试库；用例会建立和删除其中通知表以验证结构 11 → 12 的重复迁移。不要指向生产库。

关键覆盖：同事务建任务、重复申请、所有者隔离、Token 过期/撤销、实例绑定、租约代次、不可变快照、重复/迟到报告、逐对象成功与失败、回传响应丢失、发送检查点后崩溃、文件损坏/写入失败、配置修订冲突、Host/Origin/CSRF、本地重启恢复及包隔离。

## 验证边界与发布要求

自动化模拟发送不等于真实消息接口验证。真实成功/失败响应、限流、消息长度和幂等/查询能力仍需接口方提供。Linux 上通过测试不能代替 Windows 托盘显示、任务计划权限、用户代理/VPN 与注销/休眠恢复的实机验收。

CLI Wheel 与源码包须运行现有隔离检查；Windows 联网/离线分发包在后续正式流水线中还需递归复核。独立助手源码包包含自己的安装脚本，Wheel 包含网页资源；本次按用户要求作为同一 Release 的独立附件，不能进入 CLI 安装包。

按后续发布要求，三个组件版本已统一为 1.0.7.7，提供发布说明和 1.0.7.1 → 1.0.7.7 升级指南；正式发布仍须完成 CI 构建与附件复核。生产结构迁移必须执行现有项目要求的备份、恢复演练、停写和显式单进程迁移。旧版本代码只接受其对应 schema，因此不能直接把结构 12 配上旧镜像回滚；需在正式升级方案中选择经过验证的数据库恢复或降级路径，不手改 schema_versions。
