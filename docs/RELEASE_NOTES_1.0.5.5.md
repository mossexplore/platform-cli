# 1.0.5.5 源码变更说明

基于源码 1.0.5.4 优化服务日志主机选择。本次为源码提交及本地 Wheel 验证，不代表正式 Release；正式下载入口保持不变。

## 能力与兼容性

- `ml service logs SERVICE_ID` 每次先加载一页主机，每页 10 条；n/p 按需翻页，q 退出，选中后立即继续。返回已浏览页使用本次调用缓存，不再预先扫描全部主机。
- `--pod` 必须与 `--cluster-name` 成对提供。此模式仅查询第一页，以第一条记录的 infraType 确定日志类型，直接使用用户给出的 Pod 和集群；不验证其归属，要求用户确认服务主机类型一致和目标正确。
- 非交互模式有多台主机且未指定目标时，第一页后立即提示补充参数。
- 包含此前的 click 显式依赖修复，以及 infer-python 主机到日志请求 rtc_python 的正确映射。
- 旧的 `ml service host logs` 已取消注册，保留内部实现；改用 `ml service logs`。

使用前配置环境、登录并选择业务。无新增配置项或数据库迁移，不部署权限服务。手册和 skill 已同步新用法。

## 验证与限制

测试覆盖分页按需请求与缓存、参数配对、单主机自动选择、非交互提前停止、直接 Pod 模式、日志请求及版本声明；核验本地 Wheel 元数据与安装后的 ml --version。

未进行真实平台接口联调，未执行正式 Release 工作流，未重新生成 Windows 分发包或权限服务镜像。
