# 环境禁止命令开发与迁移说明

## 管理方式

权限管理系统环境编辑页新增“禁止命令”：以多行文本手动填写，每行一条包含 ml 前缀的完整业务命令。空行忽略，多余空格规范化，重复项自动去重；最多 500 条，每条最多 128 字符。页面显示禁止数量，编辑中显示新增及解除数量。规则按环境、完整叶命令精确匹配，对全部账号生效，不使用通配符。账号授权不能覆盖环境禁令。

不再维护或依赖命令目录，管理员应对照实际 CLI 的命令路径填写；保存仅校验格式，不校验命令是否存在。登录、认证、环境切换、帮助、命令树、业务选择及权限诊断入口不提供禁用。允许提前填写未来命令；无参数、通配符或自动分组展开，留空解除全部禁令。

保存前后清单进入环境修改审计；并发编辑通过行锁和策略修订号检测，陈旧表单返回 409，需刷新重试。删除环境时清理关联命令规则。

## 数据结构与源码目标

权限服务源码目标 1.0.9.1，结构从 12 升到 13；CLI 源码目标仍为 1.0.9.1。此次源码改动不表示正式发布或生产部署。

新增 `environment_command_denies`：环境外键、规范化命令、创建时间、创建管理员；环境与命令唯一。`environments` 新增 `command_policy_revision`，默认为 0。历史环境禁止清单为空，不改变既有授权。

迁移使用现有 `app.manage migrate` 显式入口，按列存在性及 `create(checkfirst=True)` 支持 MySQL DDL 中断后重跑。迁移要求单进程执行，不在多个应用进程启动时竞争修改结构。新服务健康检查要求结构 13，不能直接使用旧结构启动。

正式部署前必须先完成独立库恢复演练，再安排停写维护窗口，完成最终数据库与配置备份；之后用目标代码或目标镜像、原 service.env 和同一外部数据库执行显式迁移，核对旧账号、环境、授权未改变，再启动、验收并放行。不能重新创建已有管理员，不能修改 schema_versions 冒充迁移。

本文不替代正式发布的 Docker 升级指南。正式出包时应按仓库基准部署方式生成独立升级指南并列入附件；本次没有连接生产数据库、执行生产迁移、创建正式镜像或修改已发布附件。

## 回滚边界

没有降级迁移。旧服务不接受结构 13，不能只切回旧镜像。需恢复维护窗口前数据库备份和原配置，再启动与该结构匹配的旧服务。恢复备份会丢失备份后新增授权、规则、审计和调用日志，必须先停写并按实际业务评估。不要手动删除表或改结构版本号。

## 接口与客户端

`/api/v1/access/check` 与 `/api/v1/gateway/check` 共用环境规则。完成账号、环境和授权校验后检查命令，命中返回 `allowed=false`、`reason=COMMAND_DISABLED`，调用日志保留拒绝原因。客户端接口 HTTP 200，网关接口 HTTP 403。配置禁令时不接受缺失命令的客户端请求，返回 COMMAND_REQUIRED。版本准入保持原行为，成功码不代表业务操作已执行。

鉴权响应包含环境、平台源地址、修订号和完整禁止清单。CLI 删除本地 command_policy 仍会收到服务端拒绝，拒绝不会触发重新登录重试。Runtime、Web Studio 和 Jupyter 的现有鉴权路径均使用同一访问检查。

CLI 本地禁止清单仍可额外收紧，仅检查 jupyter files upload/download；服务端清单可限制目录中的全部业务命令。任何实际执行都不依赖缓存的“允许”结果。

成功鉴权、命令拒绝或环境列表查询可以保存服务端策略快照。缓存按权限服务地址、环境名、平台源地址隔离，只供 tree 展示；显示北京时间同步时间，旧快照可能滞后，执行时实时检查。未同步时 tree 明示状态，仍可离线和未登录使用。默认树隐藏已知禁用命令，完整树在末尾用红色 [当前环境禁用]，平台不支持优先显示 [不支持]。

## 限制与验收

这是正常 CLI 的集中管控，不是任意代码传输封禁。Jupyter exec、Notebook、终端内部行为不因禁止上传下载叶命令而自动受限。用户修改客户端、关闭权限校验或直接调用平台接口仍可能绕过客户端机制；强制控制须由可信平台或网关验证实际操作，不能信任用户转发的身份与命令字段。

需验证环境隔离、禁止与解除即时生效、旧连接缓存仍实时鉴权、CSRF 与管理员角色、并发编辑、审计前后清单、规则删除、网关同判、手动输入规范化，以及结构 12 的迁移与重复执行。SQLite 结果不能替代 MySQL 迁移和真实 Jupyter 联调。正式发布前须在 MySQL 上完成迁移及有数据页面验收。
