# 1.0.7.10 CLI 开发说明（尚未发布）

相较源码 1.0.7.9，新增 `ml service host mock SERVICE_ID --pod-ip POD_IP [--request-sample JSON] [--transmission-tag 0|1] [-o table|json]`，使用默认服务文档样例测试指定主机。先按 Pod IP 查询主机视图，再查询服务基本信息、查询文档、调用服务测试接口；最终请求的 `data.node.hostId` 取自所查主机的 `nodeId`，`data.node.hostAddress` 原样取自 `nodeHost`。服务级 `ml service mock` 保持原有调用方式，不发送 `node`。

使用前须登录、选择当前环境业务，默认使用文档样例时，目标服务须有有效 JSON 请求样例。主机测试移除 `--node-id`，仅需 `--pod-ip` 作为主机视图查询条件，不再要求用户提供测试端口。查无主机时提示“目前主机不存在，请检查！”，停止后续调用；匹配多台、查询失败或返回记录缺少有效 `nodeId`、`nodeHost` 时同样停止，不猜测主机ID或拼接地址。

`ml service host list SERVICE_ID` 不展示主机ID列；首列部署 ID 保持固定宽度 36，podIP 按 `nodeHost` 原值预留完整宽度，优先单行展示 IP 和端口，不截断，便于复制；其他长字段可换行。JSON 输出仍保留 `nodeId`。

服务测试及主机测试均新增可选 `--request-sample JSON`。未传时使用服务文档的 `requestContent`；传入时按标准 JSON 校验，保留原字符串发送到 `requestSample` 并跳过文档查询。非法报文在平台请求前提示“样例报文不是标准的JSON格式，请检查！”，包括空白、尾逗号及 NaN、Infinity 等非标准值。自定义报文不绕过主机查询。

主机列表新增可选 `--pod-ip IP`，将指定 Pod IP 写入请求体的 `hostIp`，由平台筛选结果；未传时仍发送空字符串，空值在请求前拒绝。主机测试同样使用所传 `--pod-ip` 查询主机视图。

`--transmission-tag` 默认整数 0，不调用透传接口；指定 1 调用透传接口。接口地址使用当前环境配置，全部平台请求的 `businessid` 头使用当前环境选中的业务；服务名称及版本使用服务基本信息的 `serviceInfo`，请求体租户使用 `modelInfo.businessId`。

主机测试按每个返回节点使用“字段 / 值”两列展示，行顺序为主机名称、机器规格、站点、结果码、耗时(ms)、结果报文，结果报文位于最后一行。保持完整缩进 JSON、未知字段及原始报文保留规则，展示实际返回的全部节点；普通服务测试保持六列表格，JSON 输出格式不变。Pod IP 提示写入标准错误，JSON 结果单独写入标准输出。节点失败、空节点列表或报文无效时退出 1，认证失败、超时及断连不自动重放测试；调用成功不代表内部业务结果均成功。

已有命令兼容，无权限服务、本地通知助手或数据库结构变更，无需数据库迁移。本次仅更新源码及本地包，未发布正式 Release、Windows 安装包或 Docker 镜像，正式下载入口继续指向 1.0.7.7。真实平台主机调用、IPv4/IPv6 网络连通性、Windows 原生安装及正式发布工作流尚未验证。
