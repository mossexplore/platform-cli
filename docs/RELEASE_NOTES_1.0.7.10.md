# 1.0.7.10 CLI 开发说明（尚未发布）

相较源码 1.0.7.9，新增 `ml service host mock SERVICE_ID --node-id NODE_ID --pod-ip IP:PORT [--transmission-tag 0|1] [-o table|json]`，使用默认服务文档样例测试指定主机。仍依次查询服务基本信息、查询文档、调用服务测试接口，仅在最终请求的 `data` 中增加 `node`，包含 `hostId` 和 `hostAddress`。服务级 `ml service mock` 保持原有调用方式，不发送 `node`。

使用前须登录、选择当前环境业务，目标服务须有有效 JSON 请求样例。`--node-id` 必填，取自主机列表的 `nodeId`，不可为空，以字符串发送到 `node.hostId`，保留前导零及长 ID 精度。主机地址显式传入，支持 `IPv4:端口` 和 `[IPv6]:端口`，端口范围 1–65535，无默认端口；域名、URL、无效地址或端口在平台请求前拒绝。不推断 Pod IP、主机 IP 和端口，不自动验证目标地址是否属于该服务。

`ml service host list SERVICE_ID` 在“部署 ID”后增加“主机ID”列，显示接口返回的 `nodeId`；首列部署 ID 保持固定宽度 36，主机ID 完整换行显示，缺失时显示 `-`。

`--transmission-tag` 默认整数 0，不调用透传接口；指定 1 调用透传接口。接口地址使用当前环境配置，全部平台请求的 `businessid` 头使用当前环境选中的业务；服务名称及版本使用服务基本信息的 `serviceInfo`，请求体租户使用 `modelInfo.businessId`。

复用服务测试的六列表格、完整缩进 JSON、未知字段及原始报文保留规则，展示实际返回的全部节点。目标地址提示写入标准错误，JSON 结果单独写入标准输出。节点失败、空节点列表或报文无效时退出 1，认证失败、超时及断连不自动重放测试；调用成功不代表内部业务结果均成功。

已有命令兼容，无权限服务、本地通知助手或数据库结构变更，无需数据库迁移。本次仅更新源码及本地包，未发布正式 Release、Windows 安装包或 Docker 镜像，正式下载入口继续指向 1.0.7.7。真实平台主机调用、IPv4/IPv6 网络连通性、Windows 原生安装及正式发布工作流尚未验证。

本地验证：CLI 测试 1150 项通过、12 项跳过，权限服务测试 259 项通过、1 项跳过，浏览器时区测试 3 项通过。新增覆盖主机ID列、node-id 必填与字符串保真、IPv4/IPv6、端口边界、缺失及无效地址在请求前拒绝、透传参数、目标地址仅写标准错误、全部节点保留、失败退出及不重放；现有服务测试继续验证请求不含 node。手册全部 32 章四类小节、无版本信息、实际命令树及命令帮助检查通过。Wheel 元数据、包内版本与独立安装的 `ml --version` 均为 1.0.7.10，主机测试入口及随包索引已核验。跳过项目不视为已验证。
