# 1.0.5.2 源码变更说明

本次基于源码 1.0.5.1 新增模型查询命令。正式发布状态、下载附件及平台要求以 GitHub Release 为准；本次仅提交源码并验证本地 Wheel，未执行正式发布工作流。

## 新增能力

- 新增与训练任务平级的 `ml model` 命令组。
- `ml model list` 分页查询当前业务的云侧模型，默认页码 1、每页 10 条；支持 `--name`、`--type`、`--owner`、`--team-id` 组合条件。其余请求字段保持平台约定默认值，不开放任意覆盖。
- 列表展示模型 ID、名称、模型版本、业务编码、类型、创建时间、更新时间、归属者和团队。ID 首列固定 36 字符完整展示，其他长字段换行，带时区的时间转换为北京时间。
- `ml model detail MODEL_ID` 按“字段：值”展示算法类型、版本标签、模型大小、存储方式、SFS 标识、数据源、数据源标签、更新方式和模型来源环境。
- 模型大小按 1024 进制显示 B、KB、MB、GB、TB 等单位，KB 及以上保留两位小数；例如 3271903223 字节显示为 3.05 GB。
- 两个命令支持 `--output table|json` / `-o`，默认沿用当前环境输出配置；JSON 保留完整接口响应、原始字节数、原始时间和扩展字段。

## 使用前提与兼容性

先配置平台环境、登录并选择业务。接口地址使用当前环境 `api_endpoint` 的源站；两个请求头均携带当前环境 `business.json` 的 `selected.businessId`，列表请求体同时携带该业务编码，详情请求体仅包含模型 ID。

沿用现有在线权限检查及平台查询认证刷新机制。详情响应缺少 `code` 时仍可查询；存在 `code` 时校验业务成功值。没有新增配置项或权限服务数据库迁移，现有命令保持兼容。

## 验证范围与限制

自动化测试覆盖默认请求体、组合条件和分页、环境与业务隔离、权限拒绝、详情缺少 code、业务失败和结构异常、完整 JSON、模型大小单位边界、北京时间转换、首列 ID 完整展示和认证刷新后的 JSON 可解析性。

本地检查命令帮助与完整命令树、使用手册结构、Wheel 元数据、包内版本、新模块包含情况，以及安装后的 `ml --version`。
